# AI 생성 이미지 편집기 신규 구축 계획서

작성·수정일: 2026-11-17  
상태: 신규 구현 반영 / 실제 동작·품질·성능은 배포 검증 대기  
목표: AI 생성 이미지의 정밀 보정·합성·재생성을 하나의 편집 화면에서 수행

단계별 작업 ID·선행 조건·산출물·완료 기준은 [세부 실행 계획](image-editor-implementation-roadmap.md)에서 관리한다.

## 1. 이번 계획의 확정 전제

### 1.1 지원 이미지 해상도

사용자 요구에 따라 원본 AI 이미지는 아래 세 가지 해상도로 한정한다.

| 구분 | 가로 × 세로 | 주 사용 형태 |
| --- | --- | --- |
| 가로형 | 1216 × 832 | 가로 장면·배경·복수 인물 |
| 정사각형 | 1024 × 1024 | 인물·캐릭터·정사각 구성 |
| 세로형 | 832 × 1216 | 전신·세로 인물·캐릭터 |

세 해상도 밖의 고해상도 원본, 대형 캔버스, 고해상도 출력, 업스케일은 고려하지 않는다. 성능·저장·UI·AI 입출력 검증도 이 세 가지를 기준으로 설계한다.

입력 해상도를 출력 단계에서 다시 확장하지 않도록 **작업문서와 최종 출력도 세 프리셋 안에서 운용하는 것을 이번 계획의 기본안**으로 둔다. 이는 출력 정책에 대한 설계 제안이며, 사용자가 확정한 원본 해상도 조건과 구분한다. 크롭·캔버스 변경 정책은 5절에 정리한다. 화면 확대는 픽셀을 자세히 보는 기능이며 이미지 해상도를 늘리지 않는다.

### 1.2 신규 구현 원칙

- UI, 편집 엔진, 레이어 모델, 히스토리, 저장 API, 작업문서 포맷을 새로 설계한다.
- 기존 편집기 코드·화면·컴포넌트·작업문서와의 호환을 필수 조건으로 두지 않는다.
- 기존 기능을 먼저 수리하거나 그대로 옮기는 단계, 구 작업문서 변환·마이그레이션, 구 API 호환 어댑터를 개발 범위에서 제외한다.
- 현재 구현 조사 결과는 요구사항을 발견하기 위한 참고 자료로 사용한다. 같은 기능이 필요하면 새 구조에서 다시 구현한다.
- 프로젝트·이미지 저장소·인증·생성 서비스와의 연결은 새 편집기의 연동 계약으로 정의한다. 기존 편집기 내부 구조를 그 계약으로 사용하지 않는다.

이 문서는 이전 고도화 계획을 대체한다. 기존 기초 구현·UI 문서는 과거 설계 자료이며 신규 편집기의 제약 조건이 아니다. 신규 구현 내역은 [구현 및 검증 기록](image-editor-implementation-status.md)에 관리한다. 구 편집 코드·API는 교체했으며 기존 DB·R2 데이터의 실제 삭제는 수행하지 않았다.

## 2. 제품 목표와 작업 범위

제품은 **포토샵에 가까운 편집 조작과 비파괴 작업 구조를 갖춘 AI 이미지 전용 편집기**를 지향한다. 집중할 작업은 다음과 같다.

1. 생성 이미지의 얼굴·손·옷·소품·배경 등 특정 부분을 선택하고 수정한다.
2. 브러시·복제 도장·힐링 또는 인페인트로 결함을 보정한다.
3. 캐릭터와 배경을 분리하고 다른 생성 이미지와 합성한다.
4. 색감·밝기·그림자·빛을 부분별로 조절한다.
5. 텍스트·도형·가림 효과를 추가하고 결과물을 저장한다.
6. 작업을 다시 열어 레이어·마스크·텍스트·보정값을 계속 수정한다.

포토샵에서 참고할 핵심은 선택·마스크·레이어·변형·보정·리터칭의 연결이다. 조정 레이어·마스크·원본을 보존하는 객체와 필터를 중심으로 비파괴 편집을 구성한다. [Adobe 비파괴 편집 안내](https://helpx.adobe.com/photoshop/desktop/create-manage-layers/create-layer-compositions/non-destructive-editing-techniques.html)

RAW 현상, 인쇄용 CMYK, HDR·파노라마·초점 합성, 대형 아트보드, 전문 사진 관리 기능은 이번 제품 범위에서 제외하는 것을 제안한다. PSD 교환은 핵심 편집 완성 후 필요성을 판단하는 독립 후속 과제로 두며 필수 출시 조건으로 잡지 않는다. 문서의 확대·변형·마스크·레이어 기능 수준은 유지하면서 사용 목적에 맞게 범위를 집중한다.

## 3. 현재 구현에서 확인한 요구사항

앞선 코드 조사 결과를 간단히 유지하되 신규 개발의 기능·품질 요구로 해석한다. 현재 구현은 정적 코드로 확인했으며 배포 동작을 검증한 것은 아니다.

| 영역 | 현재 구현 상태 | 신규 편집기에 필요한 수준 |
| --- | --- | --- |
| 브러시·지우기 | 색상·크기·불투명도, 브러시 레이어 지우기 | 지정 레이어/마스크, 경도·흐름·선 보정·필압 |
| 모자이크 | 브러시 마스크와 블록·강도 | 선택 영역 적용, 가림 영역 재편집, 모자이크·블러 선택 |
| 텍스트 | 생성 가능, 생성 후 내용·스타일 재편집 UI 부족 | 여러 줄·폰트·정렬·행간·테두리·그림자 재편집 |
| 도형 | 사각형·타원·선·화살표 | 변형 핸들·수치·색상·선 속성 재편집 |
| 이미지 추가 | 로컬 이미지 배치 | 자산 영속화·비율 변형·교체·작업 재열기 |
| 레이어 | 표시·잠금·이름·불투명도·삭제 | 순서·복제·그룹·다중 선택·마스크·클리핑·블렌딩 |
| 선택·변형 | 객체 사각 경계 선택·이동 | 픽셀 영역 선택, 정확한 히트 테스트, 자유 변형 |
| 보정·리터칭 | 일반 색상 보정·도장·힐링 없음 | 조정 레이어·필터·복제 도장·힐링 |
| 저장·복구 | 작업 저장·재열기, 자동 저장은 연결되지 않음 | 자산·레이어 보존, 자동 저장·로컬 복구·버전 |
| AI | 편집기 밖에 별도 인페인트 흐름 존재 | 같은 화면에서 생성하고 결과를 편집 레이어로 수용 |

조사 근거는 `public/js/image_editor.js`, `public/js/image_editor/`의 편집 모듈, `functions/[[path]].js`의 편집 API, `public/js/temp_gallery.js`·`public/js/craft.js`의 인페인트 흐름이다.

기존 구현에서는 추가 이미지의 영속 저장 누락, 원본 덮어쓰기 후 편집 중복 적용 가능성, 런타임 객체의 JSON 복사 기반 Undo, 저장 중 변경·실패 처리 문제가 확인됐다. 신규 구조에서는 각각 **자산 저장**, **원본과 출력 분리**, **명령별 이력**, **revision 기준 저장 상태**를 기본 규칙으로 삼는다. 이를 구 코드 수정 목록으로 관리하지 않는다.

## 4. 기능 구성과 우선순위

P0는 모든 기능의 기반, P1은 첫 실용 릴리스, P2는 전문 편집 완성도를 높이는 기능이다. 기존 기능 여부와 관계없이 신규 구현 항목으로 관리한다.

### 4.1 문서·레이어·보기

| 기능 | 상세 범위 | 우선순위 |
| --- | --- | --- |
| 이미지 열기 | 프로젝트/R2 이미지, 로컬 파일, 드롭·붙여넣기, 세 해상도 검증 | P0 |
| 빈 작업 생성 | 세 프리셋 선택, 투명/단색 배경 | P1 |
| 레이어 생성·관리 | 이미지·페인트·텍스트·도형·조정·효과·그룹, 이름·표시·잠금·삭제 | P0→P1 |
| 순서·복제·그룹 | 드래그 순서, 복제, 다중 선택, 그룹, 병합·평면화 | P1 |
| 자유 변형 | 이동·배율·회전·반전, 비율 유지·기준점·수치 입력, 확정/취소 | P1 |
| 정밀 변형 | 기울이기·원근·워프, 원본 자산과 변형값 보존 | P2 |
| 정렬 보조 | 레이어/캔버스 기준 정렬·분배·가이드·스냅 | P1→P2 |
| 화면 조작 | 손 도구·휠/트랙패드 줌·100%·맞춤·내비게이터·픽셀 격자 | P1 |
| 비교 | 원본 잠깐 보기·전후 분할 보기·AI 후보 비교 | P1 |
| 다중 문서 | 문서 탭, 문서별 이력·저장 상태, 문서 간 레이어 복사 | P2 |

### 4.4 AI 편집·저장

| 기능 | 상세 범위 | 우선순위 |
| --- | --- | --- |
| 인페인트 | 선택/마스크 → 프롬프트·설정 → 생성 → 후보 비교 → 레이어 추가 | P1 |
| 요청 관리 | 대기·생성 중·성공·실패·취소 상태, 생성 중 계속 편집 | P1 |
| 후보 관리 | 원본/후보 비교, 후보 보관·삭제·다시 생성, 선택 영역 밖 원본 유지 | P1 |
| 문서 저장·복구 | 레이어·자산·마스크·효과 보존, 자동 저장·로컬 복구·버전 복원 | P0→P1 |
| 결과 내보내기 | PNG/JPEG/WebP, 투명도·JPEG 배경·품질, 다운로드·프로젝트 저장 | P1 |
| 작업 프리셋 | 브러시·보정·스타일 프리셋, 선택 템플릿·반복 처리 | P2 |

인페인트는 첫 실용 릴리스에 포함한다. 현재 서비스의 생성 흐름은 입출력·인증·오류·비용 표시를 파악하는 참고 자료로 삼고, 신규 편집기는 별도 어댑터 계약으로 연결한다. 제공자가 지원하는 모델·마스크·옵션만 노출하고 Adobe 제품과 동일한 AI 모델 지원을 전제하지 않는다.

## 5. 고정 해상도 안에서의 편집 규칙

| 동작 | 제안 규칙 |
| --- | --- |
| 이미지 원본 열기·추가 | 디코딩한 실제 크기가 세 해상도 중 하나인지 확인. 그 밖의 원본은 지원하지 않는 크기로 안내 |
| 이미지 배치 | 다른 프리셋의 이미지를 현재 문서에 레이어로 넣고 배율·위치 조절. 문서 크기는 유지 |
| 크롭·프리셋 변경 | 결과는 세 프리셋 중 하나. 포함 모드는 투명/배경 여백, 채우기 모드는 넘친 부분 숨김. 확정 전 구도 미리보기 |
| 90도 회전 | 가로형↔세로형, 정사각형은 유지. 문서·레이어·마스크 좌표를 함께 변환 |
| 자유각 회전·수평 맞추기 | 캔버스 크기 유지. 바깥 부분은 숨기고 빈 영역은 투명/배경 처리 |
| 배경 생성·영역 채우기 | 고정 캔버스 안의 비어 있거나 선택된 부분에 적용. 캔버스 확장형 아웃페인팅은 범위 밖 |
| 선택 복사·패치·마스크 | 문서 일부 크기의 내부 자산 허용. 전체 원본 이미지의 지원 규격과 구분 |
| 내보내기 | 현재 문서 프리셋 크기로 출력. 고배율 출력·업스케일 옵션 없음 |
| AI 요청·응답 | 문서와 같은 크기의 합성 이미지/마스크 사용. 응답 크기가 다르면 임의 늘리기 없이 오류/재시도 처리 |

레이어를 확대해 배치하는 편집 조작은 허용하지만 문서의 픽셀 수는 늘어나지 않는다. 구도 변경·회전은 하나의 Undo 작업으로 처리하며 숨겨진 원본 내용을 보존한다. 출력 세 규격 정책을 채택하면 임의 크기 자르기 대신 프리셋 안에서 구도를 정하는 UI를 제공한다.

## 6. 신규 UI 전체 구성

### 6.1 독립 작업 화면

프로젝트에서 편집기를 열면 앱의 주 작업 영역 전체를 사용하는 독립 편집 화면으로 전환한다. 프로젝트 탐색 메뉴는 접고 편집 컨트롤을 배치한다. 이전 편집기의 화면·클래스·컴포넌트 배치를 이어받지 않고 새 작업 공간을 만든다.

기본 레이아웃은 **상단 명령/도구 옵션 + 왼쪽 도구 + 중앙 캔버스 + 오른쪽 속성/레이어 + 하단 상태**다. AI 작업도 같은 화면의 오른쪽 패널에서 수행한다.

```text
+----------------------------------------------------------------------------------+
| < 프로젝트 | 작업 이름 * | 파일 편집 이미지 레이어 선택 필터 보기 | 작업 저장 | 내보내기 |
+----------------------------------------------------------------------------------+
| 브러시 | 크기 24 | 경도 80% | 불투명도 100% | 흐름 50% | 편집 대상: 픽셀             |
+-----+------------------------------------------------------------+---------------+
| 도구 | 문서 이름 *                                                | 속성 | AI 편집 |
| 이동 +------------------------------------------------------------+---------------+
| 선택 |                                                            | 선택 도구/객체 |
| 구도 |                   투명도 체크 배경                         | 속성 및 옵션   |
| 브러시|             +-----------------------------+                | 또는 AI 입력   |
| 지우개|             |                             |                | /결과 후보     |
| 보정 |             |         편집 이미지         |                +---------------+
| 가림 |             |    선택 경계 / 변형 핸들    |                | 레이어 | 기록 |
| 문자 |             |                             |                +---------------+
| 도형 |             +-----------------------------+                | 혼합 / 불투명도|
| 손   |                                                            | 썸네일 / 마스크|
| 줌   |                                                            | 레이어 목록    |
| 색상 |                                                            | + 복제 그룹 삭제|
+-----+------------------------------------------------------------+---------------+
| 100% [맞춤] | 1024 × 1024 · 정사각형 | 원본 비교 | 로컬 복구됨 · 서버 저장됨        |
+----------------------------------------------------------------------------------+
```

위 그림은 정보 배치 초안이다. 실제 구현 전 세 프리셋과 주요 화면 상태의 UI 시안을 만든다. 최초 릴리스에서는 단일 문서 제목을 표시하고 다중 문서 단계에서 같은 위치를 탭 영역으로 확장한다.

### 6.2 영역별 규격 초안

아래 수치는 CSS 화면 배치 제안이며 이미지 지원 해상도와 무관하다.

| 영역 | 제안 크기 | 동작 |
| --- | --- | --- |
| 상단 명령 바 | 높이 약 48px | 돌아가기·작업명·메뉴·저장·내보내기 |
| 도구 옵션 바 | 높이 약 40px | 현재 도구에 따라 교체, 수치 직접 입력·초기화 |
| 왼쪽 도구 막대 | 폭 약 48px | 도구 그룹, 선택 강조, 툴팁·단축키, 전경/배경색 |
| 중앙 작업 영역 | 남은 공간 전체 | 맞춤·이동·확대, 선택·마스크·변형 표시 |
| 오른쪽 패널 | 기본 폭 약 320px, 280~400px 조절 | 상단 속성/AI, 하단 레이어/기록, 상하 분할 조절 |
| 하단 상태 바 | 높이 약 28px | 줌·규격·좌표·비교·저장 상태 |

캔버스는 사용 가능한 영역에 맞춰 표시하고 확대율을 명확히 보여준다. 패널을 열고 닫아도 현재 보고 있는 이미지 위치를 가능한 한 유지한다. 중립적인 짙은 회색 작업 배경, 투명도 체크, 이미지 바깥과 선택 영역의 명확한 대비를 기본 시안으로 제안한다.

### 6.3 시작·열기 화면

문서가 없을 때 중앙에 다음 동작을 제공한다.

- 프로젝트 이미지 열기: 폴더·검색·썸네일, 해상도·이름 표시.
- 로컬 이미지 열기: 파일 선택과 드롭, 지원 해상도 표시.
- 새 작업: 가로형·정사각형·세로형 카드와 투명/배경색 선택.
- 최근 작업: 편집문서 썸네일·프로젝트·마지막 저장 시각·복구 가능 여부.

이미지 상세에서 진입하면 선택한 원본으로 새 문서를 연다. 같은 원본의 신규 편집기 작업이 있으면 작업 이어 열기 / 새 작업을 제공한다. 구 편집기 작업문서는 목록에 섞지 않는다.

### 6.4 왼쪽 도구 그룹

| 그룹 | 포함 도구 | 캔버스 기본 동작 |
| --- | --- | --- |
| 이동·변형 | 이동·자유 변형 | 레이어 선택·드래그, 핸들 조절 |
| 선택 | 사각형·타원·올가미·다각형·색상 선택 | 픽셀 선택 영역 작성 |
| 구도 | 크롭·수평 맞추기·회전/반전 | 세 프리셋 기준 구도 변경 |
| 페인트 | 브러시·지우개·채우기·그라데이션 | 선택 레이어 또는 마스크 편집 |
| 리터칭 | 복제 도장·힐링·닷지/번 등 | 샘플 기반/국소 보정 |
| 가림 | 모자이크·블러 | 효과 마스크 칠하기 |
| 표현 | 텍스트·도형·펜 | 편집 가능한 객체 작성 |
| 보기·색상 | 손·줌·스포이트, 전경/배경색 | 뷰 이동·확대·색 샘플 |

세부 도구는 그룹 메뉴로 선택한다. 초기 릴리스에서 준비된 도구만 노출하고 후속 기능의 비활성 버튼을 나열하지 않는다. 도구 이름과 단축키는 툴팁 및 검색 가능한 명령 메뉴에서 확인한다.

### 6.5 도구 옵션 바와 속성 패널

도구 옵션 바는 지금 실행할 동작의 설정, 속성 패널은 선택된 객체의 저장되는 값을 편집한다.

| 대상 | 도구 옵션 바 | 속성 패널 |
| --- | --- | --- |
| 브러시 | 크기·경도·불투명도·흐름·선 보정 | 레이어/마스크 대상, 브러시 프리셋 |
| 선택 | 교체/추가/빼기/교차·페더 | 선택 크기·반전·확장/축소·마스크로 만들기 |
| 자유 변형 | 좌표·크기·회전·비율 잠금·확정/취소 | 정렬·기준점·원본 비율·이미지 교체 |
| 텍스트 | 폰트·크기·굵기·색상·정렬 | 내용·여러 줄·행간·자간·테두리·그림자 |
| 도형 | 종류·채우기·선 색상/굵기 | 좌표·크기·모서리·선 끝·스타일 |
| 조정 레이어 | 조정 종류·초기화 | 슬라이더·곡선·적용 대상·마스크 |
| 모자이크/블러 | 브러시 크기·칠하기/지우기 | 블록/반경·강도·효과 마스크 |
| 마스크 편집 | 대상: 마스크, 전경/배경 흑백 | 밀도·페더·반전·비활성화 |

입력 중 패널 전체를 다시 만들지 않는다. 슬라이더 드래그는 실시간 미리보기와 Undo 한 건으로 처리한다. 수치 범위·단위·초기화·직접 입력을 일관되게 제공한다.

### 6.6 레이어 패널

레이어 한 행은 표시·잠금, 내용 썸네일, 마스크 썸네일, 이름, 종류/효과 표시로 구성한다. 상단에 블렌딩·불투명도, 하단에 새 레이어·복제·마스크·조정·그룹·삭제를 둔다.

- 내용/마스크 중 실제 편집 대상을 테두리와 상태 문구로 구분한다.
- 드래그 순서 변경·그룹 접기·Shift/Ctrl 다중 선택·우클릭 메뉴를 제공한다.
- 효과·조정값은 레이어 아래 접이식 항목으로 표시하고 클릭하면 속성 패널을 연다.
- AI 결과 레이어는 생성 표시와 관련 요청/후보로 돌아가는 동작을 제공한다.
- 잠기거나 현재 도구로 수정할 수 없는 대상에는 이유와 새 보정 레이어 만들기 동작을 제시한다.
- 원본은 잠긴 이미지 레이어로 시작하고 복제·마스크·별도 보정 레이어를 통해 작업한다.

### 6.7 AI 편집 패널

AI 편집은 캔버스 조작을 유지한 채 오른쪽 상단 탭에서 진행한다. 설정이 길어지면 해당 패널 내부만 스크롤하고 하단 레이어 목록은 유지한다.

| 상태 | 표시할 내용 | 사용자 동작 |
| --- | --- | --- |
| 영역 없음 | 현재 이미지·영역 지정 안내 | 선택 도구 또는 마스크 브러시 시작 |
| 영역 준비 | 마스크 미리보기·반전·페더·원본/합성 입력 선택 | 영역 수정·프롬프트 입력 |
| 생성 설정 | 프롬프트·지원 모델·강도·seed·후보 수, 제공 가능한 경우 예상 비용 | 생성 버튼 |
| 대기/생성 중 | 작업 상태·취소·요청 영역 표시 | 계속 편집 또는 취소 |
| 결과 준비 | 후보 썸네일·원본 비교·요청 설정 | 미리보기·레이어로 추가·다시 생성 |
| 실패 | 오류 설명·설정 유지·재시도 | 수정 후 재시도 |
| 문서 변경/닫힘 | 어느 문서·revision의 결과인지 표시 | 원래 작업에서 열기 또는 후보 보관 |

후보 미리보기는 임시 표시이며 레이어로 추가를 눌렀을 때 실제 문서 변경과 Undo 한 건을 만든다. 후보 전환 시 이전 후보를 누적 합성하지 않는다. 생성 레이어에 요청 마스크를 연결해 선택 밖 내용을 유지하고 경계를 재편집한다.

수정 대상은 원본 레이어 또는 현재 합성본에서 고른다. 요청 시 문서 ID·revision·합성 이미지·마스크·설정을 고정한다. 결과는 해당 스냅샷의 후보이며 생성 중 바뀐 현재 문서를 자동으로 덮지 않는다. 생성 이후 캔버스 프리셋이 바뀌었다면 원래 revision에서 결과를 열거나 복제 작업으로 가져오게 한다.

### 6.8 비교·기록·저장·내보내기

| 기능 | UI 동작 |
| --- | --- |
| 원본 비교 | 하단 버튼을 누르는 동안 원본 표시, 고정 토글·분할 슬라이더 제공 |
| 편집 기록 | 작업명·현재 시점 표시, 클릭해 상태 이동, 새 작업 시 redo 분기 제거 |
| 서버 버전 | 파일 메뉴의 버전 기록에서 미리보기 후 새 revision으로 복원 |
| 작업 저장 | 상단 저장 버튼, 하단 미저장/로컬 복구됨/서버 저장 중/완료/실패/충돌 |
| 내보내기 | 다이얼로그에서 포맷·품질·투명도/배경·고정 해상도·위치·파일명 표시 |
| 저장 대상 | 다운로드 / 프로젝트에 새 이미지 / 기존 결과 갱신, 대상 충돌·백업 상태 안내 |

작업 저장은 레이어가 남는 편집문서이고 내보내기는 합성 이미지다. 파일 경로는 폴더 선택 UI로 지정하며 일반 사용 흐름에 R2 key 직접 입력을 요구하지 않는다.

### 6.9 입력·포커스·작은 화면

- 편집 대상·좌표·잠금·빈 선택·자산 로딩 상태를 설명한다.
- Enter는 변형 확정, Esc는 미확정 동작 취소로 통일한다. 한글 IME 조합 중에는 확정·도구 전환 단축키를 처리하지 않는다.
- Ctrl/Cmd+Z는 Undo, Ctrl/Cmd+Shift+Z 및 Ctrl+Y는 Redo 후보로 둔다. Ctrl+R은 편집 명령에 배정하지 않는다.
- Space는 손, B는 브러시, E는 지우개, V는 이동, M은 영역 선택, L은 올가미, T는 문자, I는 스포이트, 대괄호는 브러시 크기 조절을 기본안으로 둔다. 플랫폼·예약키 충돌은 구현 시 확인한다.
- 좁은 창에서는 오른쪽 패널을 서랍으로 접는다. 태블릿은 터치·핀치·필압·펜/손가락 구분을 별도 검증한다.
- 모바일은 캔버스와 도구별 하단 시트를 중심으로 구성한다. 첫 구현의 정밀 편집 기준은 데스크톱이다.
- 상태를 색만으로 구분하지 않고 이름·아이콘·포커스·화면 읽기용 이름을 함께 제공한다.

## 7. UI 시안으로 먼저 확인할 화면

기능 개발 전 아래 상태를 연결한 UI 시안을 만든다. 시안은 신규 디자인이며 기존 화면 변형을 전제로 하지 않는다.

| 시안 | 검토할 내용 |
| --- | --- |
| 시작·프로젝트 이미지 선택 | 프로젝트 연결·원본 열기·최근 작업·세 규격 안내 |
| 세로형·가로형·정사각형 각각의 편집 화면 | 중앙 공간·맞춤 배율·패널 폭·도구 접근 |
| 선택·마스크 편집 | 선택 모드·선택↔마스크·픽셀/마스크 대상 구분 |
| 자유 변형·텍스트 편집 | 핸들·수치·확정/취소·한글 입력·줄바꿈 |
| AI 요청·후보 비교 | 영역·설정·진행·후보·원본 비교·레이어 추가 |
| 저장 실패·복구·내보내기 | 상태 구분·재시도·버전 복원·포맷/위치 선택 |
| 좁은 창·태블릿 | 패널 접기·터치 대상·도구 전환 |

검토 기준은 자주 쓰는 작업이 끊기지 않는가, 현재 편집 대상이 명확한가, 원본과 결과를 빠르게 비교할 수 있는가로 삼는다.

## 8. 신규 편집 엔진과 문서 구조

### 8.1 모듈 구성

아래 경로는 제안이며 현재 생성된 코드가 아니다. 새 구현은 기존 편집기와 별도 모듈로 시작한다.

| 모듈 | 책임 |
| --- | --- |
| `public/js/editor/workspace/` | 새 UI·명령·패널·단축키·포커스 |
| `public/js/editor/document/` | 새 스키마·레이어 트리·선택·편집 상태 |
| `public/js/editor/render/` | Canvas2D 합성·마스크·블렌딩·효과·미리보기/출력 |
| `public/js/editor/tools/` | 도구 등록·pointer 수명주기·좌표·변형 |
| `public/js/editor/history/` | 속성 명령·픽셀 차분·복합 명령·메모리 예산 |
| `public/js/editor/assets/` | 원본·추가 이미지·마스크의 로딩·영속 저장·참조 |
| `public/js/editor/persistence/` | 작업 저장·자동 저장·로컬 복구·revision |
| `public/js/editor/ai/` | 제공자와 독립된 생성 요청·마스크·후보 관리 |
| `src/editor/` | 새 문서·자산·revision·출력·복구 API 서비스 |

엔진과 UI를 분리한다. 문서 변경은 명령을 통해 실행하고 도구는 begin/update/commit/cancel 규약을 공유한다. 미리보기·선택 테두리·핸들은 문서 내용과 별도로 관리한다.

### 8.2 새 작업문서

```text
schemaVersion: 새 편집기 포맷의 최초 버전
documentId / projectId / revision / baseRevision / title
canvasPreset: landscape | square | portrait
width / height: 프리셋에서 결정
color: sRGB / 8bit
assets: assetId -> 불변 저장 위치, MIME, 해시, 크기
layers: 레이어 트리, transform, opacity, blendMode, maskRef
editableData: text, shape, path, adjustment, filter parameters
generationRefs: 요청 ID, 기준 revision, 마스크, 후보 자산
outputs: 결과 key, 포맷, 원본 문서 revision
```

기존 작업문서 포맷에서 이어지는 버전 번호로 설계하지 않는다. 최초 원본은 불변 자산으로 보관하고 출력 경로와 분리한다. 프로젝트 원본이 나중에 바뀌어도 저장한 편집문서는 자신이 참조한 원본을 사용한다.

Canvas·ImageBitmap·입력 DOM·캐시는 JSON과 분리한다. 자산 저장·로딩·디코딩이 모두 끝난 뒤 문서를 준비 완료로 전환한다.

### 8.3 합성·좌표·히스토리

- 화면·문서·레이어 좌표를 분리하고 변환 행렬/역행렬을 이동·선택·마스크·변형에서 공유한다.
- 미리보기와 내보내기는 같은 합성기를 사용한다. 보정·마스크·alpha·블렌딩·그룹의 적용 순서를 명시한다.
- 레이어/마스크를 명시적으로 선택해 편집하고 선택 영역은 도구 영향을 제한하는 공통 alpha mask로 사용한다.
- 그룹·조정 레이어의 적용 범위와 클리핑 대상을 저장한다.
- 이동·속성·순서는 작은 명령, 픽셀 작업은 변경 영역의 before/after로 기록한다.
- 브러시 한 획·슬라이더 한 드래그·AI 결과 추가·프리셋 변경 하나를 각각 Undo 한 건으로 묶는다.
- 삭제·복제·그룹·병합의 Undo는 순서·선택·자산 참조까지 복원한다.
- 세션 Undo와 서버 버전은 별개다. 도구 설정·줌 변경은 이미지 미저장 변경으로 처리하지 않는다.

## 9. 세 해상도에 맞는 성능 설계

최대 픽셀 수는 1024×1024의 1,048,576개다. RGBA 8bit 전체 버퍼 한 장은 약 4 MiB이며 가로형·세로형은 조금 작다. 저장 파일 용량이 아닌 단순 픽셀 메모리 계산이다.

첫 구현은 **원해상도 Canvas2D 합성과 변경 영역 이력**을 기준으로 한다. 대형 이미지용 타일 엔진·LOD/축소 피라미드·GPU 전용 렌더러·대용량 서버 변환 파이프라인은 계획에 넣지 않는다.

레이어·마스크·Undo는 무제한 보관하지 않는다. 1024×1024의 before/after 전체 버퍼를 100번 보관하면 약 800 MiB이므로 변경 영역 차분·작은 속성 명령·재사용 캐시를 사용한다.

| 항목 | 구현 원칙 / 검증 목표 초안 |
| --- | --- |
| 렌더링 | 원해상도 캔버스, 프레임 단위 갱신, 재사용 작업 버퍼 |
| UI | 바뀐 패널만 갱신, 슬라이더·텍스트 포커스 유지 |
| 픽셀 처리 | 선택/변경 영역 중심 계산, 필터 결과 캐시 |
| 히스토리 | 메모리 예산 도달 시 오래된 세션 이력 축소, 저장 문서·서버 버전 보존 |
| 비교 | 원본/합성/AI 후보를 임시 버퍼로 전환, 문서 변경 없는 미리보기 |
| 무거운 처리 | 세 규격에서 측정해 UI가 멈추는 작업만 Worker 분리 |
| 기준 문서 | 세 규격 각각 레이어 20개·마스크 5개·조정/효과 5개 |
| 응답 목표 | 기준 문서에서 이동·줌·변형 30fps 이상, 브러시 시각 반영 p95 50ms 이내 목표 |
| 긴 작업 | 많은 획·후보·문서 전환 후 캐시·객체 URL·이미지 자원 회수 |

수치는 검증 초안이며 현재 성능이나 보장 수치가 아니다. 기준 기기·브라우저는 첫 구현에서 기록한다. 레이어·이력·후보가 문제가 되면 해당 항목을 계측·제어한다.

## 10. 신규 저장·서비스 연동

### 10.1 역할과 API 경계

| 영역 | 신규 편집기에서의 역할 |
| --- | --- |
| 브라우저 | 편집·합성·고정 해상도 출력·로컬 복구 |
| R2 | 불변 원본·추가 이미지·마스크/페인트 자산·버전·미리보기·출력/백업 |
| D1 | 새 문서 목록·최신 revision·저장 상태·자산/프로젝트/생성 요청 참조 |
| 신규 편집 API | 관리자 인증·세 규격/스키마 검증·저장·충돌·출력·복원 |
| 생성 서비스 어댑터 | 원본/합성 스냅샷·마스크·설정 입력, 고정 크기 후보 반환 |

일반 편집은 브라우저에서 처리하고 서버는 저장과 생성을 연결한다. 기존 인증·프로젝트·이미지 메타데이터 정책은 서비스 연동 조건으로 반영한다. 신규 endpoint·D1 테이블은 별도 이름과 스키마로 정의하며 구 편집 API나 테이블을 유지하기 위한 호환 개발은 하지 않는다.

### 10.2 작업 저장·복구

1. revision N과 자산·레이어·마스크·효과를 캡처한다.
2. 신규/변경 자산을 저장하고 준비 완료 여부를 확인한다.
3. `baseRevision`과 서버 최신 revision으로 충돌을 감지한다.
4. 불변 revision manifest와 자산 참조를 저장하고 최신 revision을 조건부 갱신한다.
5. 서버가 저장한 revision을 반환한다. 현재 편집이 N보다 진행됐다면 미저장 상태를 유지한다.

문서당 저장 요청을 직렬화하고 요청 ID로 중복을 처리한다. R2·D1 부분 성공은 재시도 가능한 상태로 기록한다. 실패 시 성공으로 표시하거나 미저장 작업을 버리고 이동하지 않는다.

변경을 로컬 IndexedDB 복구본에 기록하고 서버 저장은 debounce·최대 대기 시간을 둔다. 자동/수동 저장은 같은 계약을 사용한다. 종료 순간 네트워크 완료에 의존하지 않고 재열기 시 로컬 복구본과 서버 revision을 비교한다.

초기 설정안은 편집 정지 약 2초 후 서버 저장 시작, 연속 편집 시 최대 15초 간격 저장이다. 실제 빈도는 배포 계측으로 조정한다. 저장 중 편집을 허용하고 로컬/서버 실패를 구분해 재시도한다.

### 10.3 이미지 내보내기

지정 revision의 합성 결과를 문서의 고정 크기로 만든다. PNG는 투명도를 유지하고 JPEG는 배경색을 명시한다. 확장자·MIME·실제 인코딩을 일치시키고 생성 메타데이터는 서비스 정책에 맞춰 연결한다.

새 파일은 기본적으로 이름 충돌을 거부하고 다른 이름을 제안한다. 기존 결과 갱신은 대상 백업·ETag 조건을 사용한다. R2의 `onlyIf` 조건부 쓰기를 활용할 수 있다. [Cloudflare R2 API](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/)

원본 자산과 결과 출력을 분리한다. 출력이 실패해도 편집문서는 유지하고 재내보내기한다. 문서 삭제·후보 정리는 저장 버전의 자산 참조를 확인한 뒤 수행한다.

## 12. 개발 단계와 릴리스

개발 시작점은 **새 UI 시안과 문서/도구/저장 계약**이다. UI와 엔진의 연결을 먼저 검증하고 기능을 채운다.

| 단계 | 산출물 | 선행 조건 | 완료 조건 |
| --- | --- | --- | --- |
| 0. 제품·UI 설계 | 세 규격 정책, 새 시안·상태 전환, 도구·레이어·AI·저장 계약 | 이번 계획 | 7절 화면을 연결해 작업 흐름 검토 가능 |

단계 3을 첫 큰 제품 목표로 제안한다. 선택·마스크·부분 보정과 AI 재생성이 같은 화면에 연결돼야 목적을 충족한다. 후속 기능은 정밀도·작업 효율을 확장한다.

일정은 단계 0에서 화면·기능 묶음을 확정한 뒤 담당 인원과 구현 범위로 산정한다. 인페인트·자동 분리·힐링·워프는 각각 별도 기술 검토 항목이며 UI 버튼만으로 완료 처리하지 않는다.

## 13. 기존 편집기 교체 방식

1. 새 화면·모듈·포맷·API를 별도로 구현한다. 구 구조 보수·전환 어댑터를 선행 작업으로 넣지 않는다.
2. 기존 프로젝트의 일반 이미지로 새 작업을 시작한다. 구 작업문서·세션 이력·백업 읽기는 범위에서 제외한다.
3. 신규 릴리스 배포 검증 후 프로젝트/이미지 상세의 편집기 진입점을 새 화면으로 연결한다.
4. 전환 후 구 편집 모듈·UI·API·런타임 스키마 생성 코드·관련 호출을 찾아 제거한다. 필수 재사용 자산으로 남기지 않는다.
5. 다른 기능이 사용하는 인증·일반 이미지·메타데이터·생성과의 호출 경계를 확인한다.
6. 구 작업 데이터·백업의 실제 정리는 교체 구현 시 실행 범위를 명시한다. 문서 호환 개발과 데이터 정리를 구분한다.

로컬에서는 단순 구문·정적 확인, `git diff --check`, UTF-8 BOM 확인만 수행한다. 사용자 commit/push 후 Cloudflare 배포 환경에서 아래를 확인한다. 별도 요청 없이 로컬 브라우저·E2E·실서비스 연결 검증은 실행하지 않는다.

## 15. 최종 개발 방향

**고정된 세 해상도의 AI 이미지를 포토샵처럼 정밀하게 다룰 수 있는 새 편집기**를 만든다. 새 UI와 엔진을 함께 설계하고 선택·마스크·부분 보정·합성·인페인트·저장 후 재편집을 첫 핵심 완성 범위로 삼는다.

기존 편집기 보수·호환성 유지에 투입하던 범위를 제거하고 도구의 정확도, 편집 대상 표시, AI 후보 비교, 저장 신뢰성, 사용자 작업 흐름에 집중한다.
