# 게스트 이미지 alias·실제 경로명 동시 표시 수정 계획

## 1. 목적

게스트 페이지의 캐릭터 이미지 목록과 이미지 미리보기에서 alias가 설정된 이미지도 실제 파일명과 상대 경로를 함께 확인할 수 있게 한다.

이번 작업은 이미지 조회·공개 범위·R2 key 구조를 바꾸지 않고, 게스트 화면의 표시값 선택만 바로잡는 작은 UI 수정으로 한정한다.

## 2. 현재 구조와 원인

`src/guest-api.js`의 `getCharacterImages()`는 각 이미지에 이미 다음 값을 포함해 응답한다.

- `name`: alias, 상황명, 실제 파일명 순서로 결정한 표시명
- `fileName`: 확장자를 포함한 실제 파일명
- `path`: 캐릭터 폴더를 기준으로 한 실제 상대 경로
- `url`: 게스트 이미지 조회 URL

따라서 서버 응답에는 실제 경로 정보가 누락되어 있지 않다.

문제는 `public/js/guest.js`의 캐릭터 상세 이미지 렌더링에서 카드 제목, 대체 텍스트, 모달 제목, 모달 경로에 모두 `image.name || image.fileName`을 사용한다는 점이다. alias가 존재하면 `image.name`이 항상 선택되므로 `fileName`과 `path`가 화면에 나타나지 않는다.

관리자 탐색기(`public/js/explorer.js`, `public/js/modals.js`)는 alias가 있을 때 alias를 주 표시명으로 두고 실제 파일명 또는 key를 보조 정보로 함께 보여 준다. 게스트 페이지도 이 표시 규칙에 맞추는 것이 일관적이다.

## 3. 수정 범위

### 3.1 이미지 카드 표시

대상: `public/js/guest.js`

이미지별로 alias 표시 여부를 판단할 수 있는 작은 표시 로직을 두고 다음 규칙을 적용한다.

- `image.name`과 `image.fileName`이 다르면 첫 줄에 alias, 둘째 줄에 실제 파일명을 표시한다.
- alias가 없거나 두 값이 같으면 실제 파일명만 한 번 표시한다.
- 모든 동적 문자열은 기존 `escapeHtml()`을 거쳐 삽입한다.
- 긴 이름은 현재 카드 폭을 깨뜨리지 않도록 기존 `truncate` 스타일을 유지한다.

표시 예시는 다음과 같다.

```text
웃는 표정
(001.webp)
```

### 3.2 이미지 미리보기 표시

대상: `public/js/guest.js`

카드 버튼에 전달하는 dataset을 다음 의미로 분리한다.

- `data-image-title`: 캐릭터명과 alias/표시명
- `data-image-path`: `image.path`의 실제 상대 경로

이에 따라 미리보기 헤더의 제목에는 사람이 읽기 쉬운 alias를 유지하고, 바로 아래 경로 영역에는 실제 상대 경로가 표시되게 한다. `fileName`과 `path`가 동일한 단순 구조에서도 실제 파일명은 확실히 노출된다.

이미지 `alt`에도 실제 파일명을 포함해 alias만으로 이미지를 구분하기 어려운 경우를 줄인다.

### 3.3 정적 자산 캐시 갱신

대상: `public/guest.html`

`/js/guest.js`의 쿼리 버전 값을 새 값으로 변경해 Cloudflare 배포 후 브라우저가 이전 스크립트를 계속 사용하는 가능성을 줄인다.

## 4. 변경하지 않는 부분

- `src/guest-api.js`: 이미 `name`, `fileName`, `path`를 모두 반환하므로 응답 계약을 변경하지 않는다.
- `src/image-serving.js`: 이미지 접근 권한과 R2 응답 처리에는 영향이 없다.
- 게시글 이미지: 사용자가 지적한 캐릭터 이미지 alias 문제와 별개이며, 현재 게시글 이미지는 alias 계약을 사용하지 않는다.
- 관리자 페이지: 이미 alias와 실제 파일명/key를 함께 표시하므로 변경하지 않는다.

## 5. 작업 순서

1. `public/js/guest.js`에서 이미지 표시용 alias·파일명 조합 로직을 정리한다.
2. 캐릭터 이미지 카드에 alias와 실제 파일명을 함께 렌더링한다.
3. 미리보기 modal의 경로 dataset에 `image.path`를 연결하고 대체 텍스트를 보완한다.
4. `public/guest.html`의 `guest.js` 버전 쿼리를 갱신한다.
5. 정적 검사와 변경 diff 검토를 수행한다.

## 6. 검증 계획

프로젝트 규칙에 따라 로컬에서는 브라우저/E2E 테스트를 실행하지 않고 정적 검사만 수행한다.

### 6.1 로컬 정적 검증

1. `node --check public/js/guest.js`
2. `git diff --check`
3. `git diff`로 API·이미지 접근 제어 등 계획 밖 변경이 없는지 확인
4. 수정한 텍스트 파일이 UTF-8 BOM 바이트 `EF BB BF`로 시작하지 않는지 확인

### 6.2 Cloudflare 배포 후 확인 시나리오

1. alias가 있는 이미지 카드에 alias와 실제 파일명이 모두 표시된다.
2. alias가 없는 이미지 카드에는 실제 파일명이 중복 없이 한 번만 표시된다.
3. 하위 폴더에 있는 이미지를 열면 미리보기의 경로 영역에 실제 상대 경로가 표시된다.
4. 긴 alias·파일명·경로가 카드와 모달 레이아웃을 깨뜨리지 않는다.
5. 이미지 클릭, 모달 닫기, 뒤로 가기, 키보드 포커스 복원 동작이 기존과 동일하다.
6. 다크 모드와 모바일 화면에서 두 줄 표시가 읽을 수 있는 상태로 유지된다.

## 7. 완료 기준

- alias가 있는 게스트 이미지에서도 실제 파일명과 상대 경로를 확인할 수 있다.
- alias가 없는 이미지의 이름은 중복 표시되지 않는다.
- 서버 API, R2 key, 이미지 공개 정책은 변경되지 않는다.
- 로컬 정적 검사와 BOM 검사를 통과한다.
- 실제 동작은 사용자가 변경을 커밋·푸시한 뒤 Cloudflare 배포 환경에서 확인한다.
