# 생성된 플랜 전체 보기 구현 계획

작성일: 2026-11-08
상태: 검토 승인 후 구현 완료 — 로컬 문법·정적 검사 완료, Cloudflare 배포 후 실제 동작 확인 예정.

## 1. 요구사항과 표시 기준

현재 프로젝트의 플래너에 `생성된 플랜 전체` 보기를 추가한다. 특정 캐릭터나 상황을 선택하지 않고, 실제 저장된 플랜을 한 화면에서 확인한다.

- 여기서 ‘생성된 플랜’은 서버에서 조회한 캐릭터별 planner meta의 `items`에 존재하는 저장된 항목이다.
- 이미지 생성 여부와 관계없이 저장된 플랜이면 포함한다. 실행 대기, 생성 중, 실패, 후보 검토 등 기존 상태를 유지한다.
- 캐릭터 × 상황의 모든 가능한 조합을 만들지 않는다. 저장된 item이 없는 조합은 표시하지 않는다.
- 최종 이미지만 있고 플랜 item이 없는 조합과, 아직 저장하지 않은 편집 내용은 포함하지 않는다.
- 현재 프로젝트의 캐릭터/상황에 연결되는 플랜을 대상으로 한다. 삭제된 캐릭터나 상황의 잔존 데이터 복구는 이번 범위에 포함하지 않는다.

예: 캐릭터 A·B, 상황 1·2·3 중 A/1, A/3, B/2의 플랜만 저장되어 있다면 카드도 정확히 3개만 표시한다.

## 2. 현재 구조와 변경 방향

| 현재 구현 | 변경 방향 |
| --- | --- |
| `planner.js`의 scope는 `character`, `situation` 두 값으로 정규화·저장됨 | `all`을 추가하고 저장·복원·전환 조건을 함께 수정 |
| 캐릭터 기준은 상황 목록, 상황 기준은 캐릭터 목록을 순회하여 미작성 카드까지 생성 | 전체 보기는 캐릭터별 `meta.items`만 순회하는 별도 목록 생성 함수 사용 |
| `loadPlannerSituationScopeData()`가 여러 캐릭터의 플랜·이미지·설정을 조회 | 상황/전체 보기에서 공유할 데이터 로더와 상태로 일반화 |
| `manage.js`의 첫 진입, 새로고침, 탭 복귀에서 상황 보기만 추가 로드 | 전체 보기에도 같은 진입·갱신 경로 적용 |
| 일괄 생성/삭제는 상황 이외 scope를 캐릭터로 처리하는 분기가 있음 | 전체 보기에서는 두 동작을 숨기고 함수 진입도 명시적으로 차단 |

기존 캐릭터별 compact 조회 API와 저장 구조를 재사용한다. 서버 API, D1 스키마, migration 변경은 계획하지 않는다.

## 3. 화면 구성

1. `캐릭터 기준 | 상황 기준 | 생성된 플랜 전체` 버튼을 제공한다.
2. `플랜 · 결과`의 전체 보기에서는 대상 선택기를 숨기고 `현재 프로젝트의 저장된 플랜 N개`를 표시한다. 다른 보기로 돌아오면 이전 대상 선택을 유지한다.
3. 카드는 기존 그리드를 사용하며 캐릭터명과 상황명을 모두 표시한다. 검색도 두 이름을 대상으로 한다.
4. 정렬은 기존 캐릭터 목록 순서 → 기존 상황 목록 순서로 고정한다. prompt variant별로 카드를 나누지 않고 기존처럼 캐릭터/상황 item당 카드 하나를 표시한다.
5. 카드의 후보 수, 상태, 대표 이미지 선택 규칙과 편집/검토 진입 동작을 재사용한다.
6. 실행 화면의 대상 캐릭터 선택과 실행 범위는 기존 동작을 유지한다. 전체 보기 선택이 프로젝트 전체 실행을 뜻하지 않도록 한다.

### 필터와 일괄 작업

- 전체 보기에는 `전체`, `검토` 필터를 제공하고 `미작성`은 숨긴다. `검토`의 판정은 기존 동작을 유지한다.
- 미작성 필터에서 전체 보기로 전환하면 필터를 `전체`로 초기화한다. 검색어는 유지한다.
- 검색 결과가 없으면 `검색 조건에 맞는 플랜이 없습니다.`를 표시한다.
- 저장된 플랜 자체가 없으면 `생성된 플랜이 없습니다. 캐릭터 기준 또는 상황 기준에서 플랜을 작성하세요.`를 표시한다.
- `누락 플랜 생성`, `전체 플랜 삭제`는 전체 보기에서 숨긴다. 이번 요구는 조회 범위 확장이므로 프로젝트 전체 일괄 작업은 추가하지 않는다.
- 개별 플랜 편집, 이미지 생성/재생성, 후보 선택, 삭제는 기존 권한과 작업 중 제한을 유지한다.

## 4. 조회와 상태 관리

1. 전체 보기 최초 진입 시 캐릭터별 저장 플랜을 읽는다. 기존 조회 코드와 캐시를 공유하고, 캐릭터가 많을 때 요청이 몰리지 않도록 동시 요청 수를 제한한다.
2. 전체 목록용으로 모든 캐릭터의 파일·설정을 먼저 조회하지 않는다. 플랜이 있는 캐릭터의 카드에 필요한 이미지 정보만 추가 조회하고, 편집용 데이터는 기존 모달 진입 경로에서 확보한다. 상황 보기에 필요한 기존 로딩 계약은 보존한다.
3. 조회 결과를 `{ character, situation, item, meta }` 목록으로 구성한다. 현재 목록에서 유효한 캐릭터/상황을 연결하고, 캐릭터 ID + 상황 ID로 카드를 식별한다.
4. 새로고침은 서버를 다시 조회한다. 저장·삭제·생성 상태 갱신 후에는 공유 meta와 전체 목록을 함께 갱신한다. 서버 응답에서 사라진 항목도 캐시에서 제거한다.
5. 프로젝트/보기 전환 중 늦게 완료된 요청이 다른 화면을 덮지 않도록 기존 operation ID와 프로젝트 검증을 확장한다.
6. 일부 캐릭터의 조회가 실패해도 성공한 플랜은 표시한다. 실패한 캐릭터와 재시도 안내를 별도 배너에 표시하고, `확인된 플랜 N개 · 일부 조회 실패`로 불완전한 집계임을 명시한다. 실패를 빈 플랜으로 간주하지 않는다.
7. 이미지 조회만 실패하면 플랜은 유지하고 기존 placeholder를 사용한다. 모든 플랜 조회가 실패하면 빈 목록 대신 오류와 재시도를 표시한다.
8. 전체 보기 선택은 기존 프로젝트별 localStorage에 저장한다. 기존 저장값은 정상 복원하고, 알 수 없는 scope만 캐릭터 기준으로 되돌린다.

## 5. 기존 작업과의 연결

- 전체 목록에서도 카드가 가진 캐릭터/상황 ID로 정확한 meta를 찾아 편집·검토한다. 헤더에서 선택된 캐릭터로 대체하지 않는다.
- 이전/다음 플랜 이동은 현재 검색·필터로 보이는 전체 목록 순서를 따른다.
- 삭제한 플랜은 전체 목록에서 즉시 사라진다. 마지막 플랜 삭제 시 빈 상태로 바뀐다.
- 다른 보기에서 새 플랜을 저장한 뒤 전체 보기로 전환하면 해당 플랜을 표시한다.
- 생성 폴링, 개별 삭제, 최종 선택 완료 등 item을 갱신/제거하는 경로가 공유 상태에도 반영되는지 확인한다.

## 7. 검증 및 적용 순서

1. 검토 후 표시 기준과 UI 제안을 확정한다.
2. scope 저장·복원 및 데이터 로딩을 확장한다.
3. 저장된 item만 표시하는 전체 목록과 필터/빈 상태/오류 처리를 연결한다.
4. 개별 작업과 이전/다음 이동, 캐시 갱신, 일괄 작업 가드를 점검한다.
5. 로컬에서는 변경 JS의 `node --check`, `npm run check:planner-workspace`, `git diff --check` 등 문법·정적 검사만 수행한다. 수정한 텍스트 파일의 UTF-8 BOM 부재를 확인한다.
6. 사용자가 커밋·푸시한 후 Cloudflare 배포 서버에서 아래 동작을 확인한다. 로컬 브라우저/E2E/실서비스 테스트는 실행하지 않는다.

배포 후 확인 항목:

- 가능한 조합 6개, 저장 플랜 3개인 예제에서 카드가 3개만 표시됨.
- 이미지가 없는 저장 플랜은 보이고, 이미지만 있는 미작성 조합은 제외됨.
- 캐릭터명/상황명 검색, 필터, 저장된 보기 복원, 프로젝트 전환이 정상 동작함.
- 다른 캐릭터의 카드도 정확히 편집·검토·삭제되고 이전/다음 이동이 표시 순서를 따름.
- 새로고침, 플랜 추가·삭제, 생성 상태 변경 후 목록과 개수가 갱신됨.
- 부분 조회 실패가 빈 목록으로 오인되지 않고 재시도가 가능함.
- 기존 두 보기와 실행 화면의 범위가 유지됨.

## 8. 검토 후 확정 사항

1. ‘생성된 플랜’의 기준: 이미지 생성 완료가 아니라 **저장된 플랜 item 존재**.
2. 보기 이름: **생성된 플랜 전체**.
3. 전체 보기의 프로젝트 일괄 생성/삭제는 제공하지 않고 **개별 작업만 제공**.
4. 기본 정렬: **캐릭터 순서 → 상황 순서**.

## 9. 구현 반영 내용

- 상황/전체 보기의 공유 조회는 `loadPlannerMultiScopeData()`와 `plannerMultiScopeState`로 통합했다.
- 캐릭터별 조회는 최대 4개 작업으로 제한하고 전체 보기에서는 플랜이 있는 캐릭터의 이미지 정보만 추가 조회한다.
- 저장된 항목을 순회하여 유효한 캐릭터/상황만 연결하며, 비어 있는 조회 결과도 기존 캐시보다 우선한다.
- 조회 중 저장·삭제·생성 상태 갱신이 완료된 경우 해당 갱신 결과를 유지한다. 프로젝트/보기 전환으로 무효화된 조회 결과는 적용하지 않는다.
- 첫 진입과 재진입, 새로고침, 저장·삭제·확정 및 생성 상태 갱신 경로를 연결했다.
- 프로젝트 모듈 및 CSS 캐시 버전을 `planner-workspace-20261108a`로 동기화했다.
- 로컬 브라우저/E2E 테스트, 커밋·푸시 및 배포는 수행하지 않았다.
