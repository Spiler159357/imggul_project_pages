# 이미지 생성 탭 UI·반응성 개선 구현 기술서

작성일: 2026-11-05  
상태: 코드 수정 및 로컬 정적 검사 완료 · 배포 검증 대기  
대상: 이미지 생성 탭의 일반 생성·Inpaint와 공용 진행 UI

## 1. 목표와 범위

1. Inpaint 진입 및 모델 전환 시 생성 버튼에 잘못 표시되는 Anlas 문구를 수정한다.
2. 모바일에서 생성 클릭 직후 상태를 표시하고, 사전 조회 지연·통신 실패·504 발생 시 처리 단계와 결과를 구분한다.
3. 오른쪽 아래 생성 현황 인디케이터의 긴 변환·저장 문구가 영역 밖으로 넘치지 않도록 한다.

이번 문서는 구현 요구사항을 정의하고 마지막 절에 코드 반영 결과를 기록한다. 배포 검증 결과 보고서는 아니다. 로컬에서는 코드 검토와 간단한 정적·구문 검사만 수행하고, 실제 동작은 사용자가 커밋·푸시한 후 Cloudflare 배포 서버에서 검증한다.

## 3. Anlas 표시 요구사항

### 3.1 표시와 비용 계산의 분리

- 생성 버튼의 Anlas 숫자·소모량 문구는 정규화된 모델 프로필의 `family === 'v5'`인 경우에만 표시한다. 무료 상태는 기존처럼 `생성`을 표시한다.
- 비 V5 모델의 생성 버튼 기본 문구는 `생성`으로 유지한다. Inpaint 진입·해제만으로 Anlas 문구가 버튼에 추가되어서는 안 된다.
- 비용 계산과 비용 증가 시 재확인 보호는 모든 모델에서 유지한다. 비 V5에서도 큰 해상도, 높은 steps, 비 Opus 구독, Precise Reference 등 실제 비용 발생 조건은 존재한다.
- 비 V5 유료·불확실 상태는 버튼 가까이의 별도 비용 안내 영역에 표시한다. 비용 확인이 필요한 상태를 버튼 문구와 title만으로 안내하지 않는다. 모바일에서도 안내를 읽을 수 있어야 한다.
- 구독 조회 실패를 무료로 취급하지 않는다. `확인 불가`와 가능한 비용 범위를 구분해서 안내한다.
- 위 구독·가격 내용은 저장소의 `docs/novelai-anlas-policy.md`와 현재 계산 구현을 기준으로 한 것이다. 외부 서비스의 최신 요금 정책을 새로 검증한 문서는 아니다.

### 3.2 상태 갱신

- 모델 전환, Inpaint 이미지 설정·해제, 해상도·steps·반복 횟수 변경, 구독 조회 완료 시 현재 선택 모델 기준으로 표시를 다시 계산한다.
- V5에서 비 V5로 전환하면 이전 Anlas 버튼 문구와 관련 title을 정리한다.
- 오래 걸린 구독 응답이 도착해도 과거 모델의 표시를 복원하지 않는다.
- 생성 준비가 시작되면 모델·설정의 스냅샷을 사용한다. 요청 비용·승인 비용·실제 큐 작업은 같은 스냅샷을 기준으로 한다.
- 실행 직전 비용 증가로 중단할 경우, 화면에 명확한 안내를 남기고 변경된 비용을 확인한 사용자의 다음 실행에서만 진행한다.

## 4. 생성 반응성과 통신 처리 요구사항

### 4.1 상태와 중복 실행 방지

논리 상태는 `idle → preparing → checking-cost → preprocessing → requesting → receiving → unpacking → converting(필요 시) → uploading → completed`로 구분한다. 실패는 `failed`, 생성 요청 전 취소는 `cancelled`, 요청 전송 후 결과 확인 불가는 `result-unknown`으로 구분한다. 구현 시 기존 큐 상태와 매핑하되 서로 충돌하는 플래그를 늘리지 않는다.

1. 함수 진입 시 동기적으로 준비 잠금을 획득한다. 첫 await 이전부터 연속 탭과 다른 호출 경로의 중복 진입을 차단한다.
2. 네트워크 대기를 시작하기 전에 버튼과 인디케이터에 `생성 준비 중` 또는 `비용 확인 중`을 표시한다. 목표는 클릭 후 다음 렌더링 기회에 상태가 반영되는 것이다.
3. 이미지 전처리 등 무거운 작업 전에 화면이 그려질 기회를 준다. 타이머 추가만으로 CPU 비용이 해결되었다고 판단하지 않는다.
4. 비용 변경에 따른 조기 반환, 전처리 예외, 저장 예외, 취소 등 모든 종료 경로에서 잠금·버튼·타이머를 정리한다. 큐 실행기로 소유권을 넘긴 뒤 준비 단계의 finally가 실행 중 UI를 숨기지 않도록 한다.
5. 준비 단계에서 취소하면 이후 await가 완료되어도 큐에 적재하거나 생성 요청을 보내지 않는다. 진행 중 취소 시에는 새 작업 전송을 중단하고 현재 요청의 처리 여부를 정확히 표시한다.
6. 준비 중 설정 변경은 잠그거나 스냅샷에서 분리한다. 뒤늦은 응답이 다른 작업의 UI를 덮지 않도록 작업 식별자를 확인한다.

### 4.2 구독 조회 대기 제한

- 구독 조회의 제한 시간은 초기 제안값으로 클라이언트 10초, 서버 upstream 8초를 사용하고 상수로 관리한다. 이 값은 서비스 보장 시간이 아니라 구현 기본값이다.
- 타임아웃은 응답 헤더 수신뿐 아니라 JSON 본문 읽기까지 포함한다. 성공·실패·중단 시 타이머와 요청 공유 상태를 정리한다.
- 같은 생성 시작에서 완료한 조회를 바로 강제 재조회하지 않는다. 기존 30초 캐시·진행 중 Promise 공유를 활용한다.
- 반복 생성 도중에는 캐시 만료와 잔여 비용 변화를 고려해 다시 확인한다. 조회 횟수를 줄이기 위해 비용 증가 보호를 제거해서는 안 된다.
- 시간 초과·오류 시 오래된 정보를 최신 정보로 표시하지 않는다. 확인 불가 비용 범위를 표시하고 기존 승인 범위를 넘으면 전송을 보류한다.

### 4.3 생성 요청·504·결과 불확실성

- 구독 조회와 생성 요청의 제한 시간을 분리한다. 생성 요청에 구독 조회용 10초 제한을 적용하지 않는다.
- 생성 응답·본문 읽기에도 유한한 대기 한도를 둔다. 초기 클라이언트 제안값은 180초이며, 배포 경로의 실제 제한과 관측 지연을 확인해 조정한다. 임의로 Cloudflare 제한을 단정하지 않는다.
- HTTP 오류 응답이 JSON, HTML, 일반 텍스트 중 어느 형식이어도 안전하게 처리한다. 긴 HTML이나 서버 원문을 인디케이터에 그대로 출력하지 않는다.
- 서버가 응답을 구성할 수 있는 오류는 JSON 형식으로 `error`, `code`, `stage`, `upstreamStatus`, `requestId`를 제공한다. 예: 구독 조회 시간 초과와 생성 upstream 504를 다른 코드로 구분한다.
- 생성 upstream의 HTTP 상태를 보존하고, fetch 자체 실패는 502, 서버 자체 제한 시간 초과는 504 등으로 구분한다. 게이트웨이가 직접 반환하는 오류는 이 JSON 형식을 보장할 수 없으므로 클라이언트 fallback을 유지한다.
- 생성 요청 전 실패는 `생성을 시작하지 못했습니다`, 전송 후 504·연결 끊김은 `응답을 확인하지 못했습니다. 생성이 처리되었을 수 있습니다`처럼 구분한다.
- 생성 요청 전송 후 결과가 불명확하면 자동 재전송하지 않는다. 반복 큐의 후속 작업도 보류하고, 사용자가 결과 확인 후 명시적으로 다시 실행하도록 한다. 이미 정상 완료한 결과를 삭제하지 않는다.
- AbortController로 클라이언트 대기를 중단해도 upstream 생성 취소나 과금 취소가 보장된다고 안내하지 않는다.

### 4.4 단계별 진단 정보

- 기존 로그 함수를 활용해 준비 시작, 구독 조회 시작·종료, 전처리 시작·종료, 생성 전송 직전, 응답 수신, 본문 수신 완료, 압축 해제, 변환, 업로드, 실패를 기록한다.
- 작업 ID, 요청 ID, 단계, 경과 시간, HTTP 상태, upstream 상태, 제한 시간 여부를 기록한다. 서버가 요청을 받았는지와 클라이언트 전송 시도 여부는 구분한다.
- 토큰, 이미지·마스크 base64, 전체 프롬프트, 서버 응답 전체를 진단 로그에 추가하지 않는다.
- 별도 서버 작업 조회 API가 없는 현재 경로에서는 requestId만으로 생성 완료 여부를 복구할 수 없다. 영속 작업·멱등성·자동 복구 API 도입은 이번 범위에 포함하지 않는다.

## 5. 생성 현황 인디케이터 요구사항

### 5.1 레이아웃

- 플로팅 본문 flex 자식에 `min-width: 0`을 적용하고 불필요한 `w-full` 충돌을 제거한다. 아이콘과 퍼센트는 축소되지 않게 한다.
- 오버레이는 데스크톱의 기존 크기를 기준으로 하되, 실제 부모 컨테이너 너비에서 좌우 여백을 뺀 값보다 커지지 않도록 최대 너비를 제한한다.
- 상태 문구는 한 줄 말줄임으로 표시한다. 전체 안내는 별도 상세 영역 또는 펼침 동작으로 확인할 수 있게 하며 모바일에서 title만으로 대체하지 않는다.
- 진행 바와 퍼센트는 긴 문구에도 영역 안에 유지한다. 사이드 진행 UI에도 동일한 축소·넘침 방지 규칙을 적용한다.
- 준비·실패·비용 변경 안내는 보조기기에서도 읽을 수 있게 한다. 100ms마다 갱신되는 퍼센트를 매번 음성으로 알리지 않는다.

### 5.2 문구와 진행률

| 단계 | 기본 표시 문구 | 표시 규칙 |
| --- | --- | --- |
| 준비 | 생성 준비 중 | 진행률 미정 |
| 구독·비용 확인 | 비용 확인 중 | 진행률 미정 |
| 전처리 | 이미지 준비 중 | 진행률 미정 |
| 생성 요청 | 생성 응답 대기 중 | 응답 전 추정치임을 구분 |
| 본문 수신 | 결과 수신 중 | 본문 읽기 완료 전 다운로드 완료라고 표시하지 않음 |
| 압축 해제 | 압축 해제 중 | 생성 추정 타이머 종료 |
| 변환 | 이미지 변환 중 | 실제 변환 경로에서만 표시 |
| 업로드 | 이미지 저장 중 | 변환과 별도 표시 |
| 완료 | 생성 완료 | 저장까지 성공한 경우 100% |
| 실패 | 비용 확인 실패 / 생성 응답 오류 / 이미지 저장 실패 등 | 현재 실패 단계에 맞는 짧은 문구, 상세는 별도 제공 |

- 반복 횟수, 단계 문구, 예상 남은 시간은 가능한 한 별도 요소로 나눈다. 긴 문자열 하나에 모두 연결하지 않는다.
- 남은 시간 추정은 생성 단계에만 적용한다. 압축 해제·변환·저장에 생성 시간 기반 추정치를 붙이지 않는다.
- 현재 일반 생성 경로와 플래너 경로의 변환 방식이 다르다. `processDelayedWebPConversion()`의 과거 이미지 지연 변환을 현재 생성 작업의 필수 변환 단계처럼 표시하지 않는다.
- 구독 확인 중에도 현재 타이머가 `추론 진행 중`을 표시할 수 있으므로 생성 추정 타이머는 실제 생성 요청 단계에서 시작하도록 이동한다.

## 7. 검증 및 완료 기준

### 7.1 로컬 화이트박스 검토·정적 검사

- 모델별 비용 계산, 버튼 문구, 별도 비용 안내, 승인 비용 검사를 각각 추적한다. 실제 브라우저나 서비스를 호출하지 않는다.
- 아래 분기표의 결과를 코드 기준으로 점검한다.

| 조건 | 기대 결과 |
| --- | --- |
| 비 V5 + 무료 조건의 Inpaint | 버튼은 `생성`, 무료 계산 유지 |
| 비 V5 + 유료 조건의 Inpaint | 버튼은 `생성`, 별도 비용 안내 및 비용 증가 보호 유지 |
| V5 + Inpaint | 버튼에 비용 표시, 요청 모델은 해당 Inpaint 모델 |
| V5 → 비 V5 전환 / Inpaint 해제 | 이전 버튼 문구가 남지 않음 |
| 구독 확인 불가 | 무료 확정 금지, 비용 범위와 실행 보류 조건 적용 |
| 준비 중 중복 호출·취소 | 큐 중복 적재·늦은 요청 전송 방지 |
| 비용 변경·전처리 예외·JSON 읽기 실패 | 잠금과 UI 복구, 타이머 정리 |
| 생성 504·본문 읽기 중 연결 끊김 | 결과 불확실 안내, 자동 재전송·후속 큐 전송 보류 |
| 긴 상태 문구·긴 오류 원문 | 짧은 상태 표시와 상세 분리, 최소 너비 제한 확인 |

- 수정한 JS에 `node --check`를 실행한다. 기존 검사 스크립트는 내용을 검토해 외부 통신·브라우저 실행이 없는 단순 검사만 사용한다.
- `git diff --check`로 공백 오류를 확인한다. 수정한 모든 텍스트 파일이 UTF-8이고 시작 바이트가 `EF BB BF`가 아닌지 확인한다.
- 정적 검토로 모바일 렌더링·네트워크 타이밍·실제 504 해결을 입증했다고 보고하지 않는다.

### 7.2 커밋·푸시 이후 Cloudflare 배포 검증

사용자가 커밋·푸시한 이후 배포 서버에서 다음을 검증한다. 생성 호출은 실제 비용이 발생할 수 있으므로 필요한 최소 사례로 제한한다.

1. 모바일 320·360·390·430px 및 데스크톱에서 모델 전환, Inpaint 진입·해제, 비용 안내를 확인한다.
2. 생성 클릭 직후 준비 상태가 보이고, 연속 탭이 중복 생성으로 이어지지 않는지 확인한다.
3. 구독 조회 지연·실패와 생성 응답 지연·504를 단계별 로그 및 요청 식별자로 구분한다. 비용 재확인으로 보류될 때 안내가 보이는지 확인한다.
4. 본문 수신·압축 해제·실제 변환·저장 단계에서 문구가 맞고, 긴 한글·영문 무공백 문구와 큰 반복 횟수에서도 가로 넘침이 없는지 확인한다.
5. 오류·취소 이후 버튼을 다시 사용할 수 있고, 결과 불확실 상태에서는 자동으로 다시 생성하지 않는지 확인한다.
6. 공용 생성 함수를 사용하는 플래너와 큐 복구의 정상 완료·실패 이벤트가 유지되는지 확인한다.

완료 판정은 세 UI 문제의 배포 확인과 오류 처리 분기 검토를 함께 근거로 한다. 504 원인이 외부 서비스 또는 게이트웨이에 남아 있으면 그 한계를 기록하며, 단순 타임아웃 추가를 504 원인 해결로 보고하지 않는다.

## 8. 코드 반영 결과 및 남은 검증

- `public/js/generation-feedback.js`에 모델별 버튼 표시 정책, 제한 시간 처리, 안전한 HTTP 오류 분류를 분리했다. 비용 계산식은 유지했다.
- 생성 준비에 동기 잠금과 입력 비활성화·복원, 설정 스냅샷, 취소 후 전송 방지, 준비 실패 안내를 추가했다. `generateNaiImage()`는 큐 인계 여부를 boolean으로 반환한다.
- 구독 조회는 클라이언트 10초, 서버 8초로 제한했다. 정상 캐시는 기존 30초, 실패 캐시는 연속 중복 조회 방지용 5초다. 강제 갱신과 진행 중 요청 공유는 유지한다.
- 생성 클라이언트 대기는 본문 읽기를 포함해 180초, 서버 upstream 대기는 스트림 본문을 포함해 165초로 제한했다. 이미지 전처리·변환에는 30초 제한을 적용했다. 이 값들은 프로젝트 기본값이며 Cloudflare 서비스 제한을 의미하지 않는다.
- `src/novelai-proxy.js`에서 upstream HTTP 상태·실패 단계·요청 ID를 전달한다. 성공 ZIP은 전체 버퍼링 대신 스트림으로 전달한다. 헤더 전송 이후 본문 실패는 JSON 오류로 바꿀 수 없으므로 서버 로그와 클라이언트의 결과 불확실 안내로 처리한다.
- 전송 중에는 현재 작업과 후속 큐를 자동 복구 저장 대상에서 제외한다. 정상 저장 완료 후에만 남은 미전송 큐를 다시 저장한다. 브라우저 종료 시 미전송 후속 큐까지 자동 재개되지 않을 수 있는 의도적인 변경이다.
- 처리 실패도 후속 생성으로 가리지 않도록 큐를 중지한다. 실패·비용 변경 안내는 사이드바와 닫을 수 있는 별도 알림에 남긴다. 결과 조회·파일 복구 API는 추가하지 않았다.
- 인디케이터 본문의 최소 너비·최대 너비·말줄임을 보완하고, 상세 펼침을 추가했다. 변환과 저장을 구분하며 예상 남은 시간은 생성 단계의 상세에만 표시한다.
- 공용 생성 함수를 사용하는 플래너는 호출 전에 완료 이벤트를 구독하고, 준비 중단 시 구독을 정리해 무한 대기를 방지한다. 변경된 프런트엔드 모듈의 버전 쿼리도 갱신했다.
- 기존 `scripts/check-novelai-v5.mjs`에 V5·비 V5, 무료·유료·구독 불명, Inpaint 28·29 steps의 비용/표시 분기 검사를 추가했다. 외부 통신이나 브라우저를 실행하지 않는 검사다.

다음 로컬 검사를 완료했다.

- 변경한 JS 8개 파일의 `node --check` 통과.
- `node scripts/check-novelai-v5.mjs`: 모델·비용 및 추가한 표시 분기 검사 통과.
- `node scripts/check-prompt-metadata.mjs`: 프롬프트 메타데이터 검사 통과.
- `node scripts/check-planner-background-recovery.mjs`: 기존 플래너 정적 검사 통과.
- `git diff --check`, 변경·추가 텍스트 파일 10개의 UTF-8 및 BOM 없음 검사 통과.
- 추가한 안내·상세 표시용 HTML ID의 중복 없음 확인.

실제 모바일 레이아웃, 클릭 반응 시간, upstream 504 발생 경로는 7.2의 배포 검증 항목으로 남긴다. 로컬 브라우저·E2E·서비스 테스트와 커밋·푸시·배포는 수행하지 않았다.
