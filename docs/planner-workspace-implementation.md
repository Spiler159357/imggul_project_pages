# 플래너 통합 작업 공간 구현

## 화면과 동작

- `플랜 · 결과`와 `실행 화면`의 두 화면으로 통합한다. 이전 `result` 값은 화면 진입 시 `plan`으로 정규화한다.
- 메인은 캐릭터 기준/상황 기준의 전체 플랜 그리드다. 그리드 안에서 스크롤하며 전체/미작성/검토 필터와 이름 검색을 제공한다. 미작성은 플랜·최종 이미지가 없는 조합, 검토는 플랜·후보 이미지가 있는 조합이다.
- 누락 플랜 생성·전체 플랜 삭제는 메인에 직접 배치한다. 새로고침은 오른쪽 끝이다. 대상 범위와 일괄 생성/삭제 제약은 기존 엔진을 사용한다.
- 후보가 있는 플랜은 확대 검수, 없는 플랜은 편집으로 진입한다. 검수 중 프롬프트 수정, 편집 후 검수 이동, 이전/다음 플랜 탐색을 제공한다.
- 핵심 프롬프트와 V4 캐릭터 필드는 접지 않는다. 저장 버튼은 편집 화면을 유지한다. 중복 저장하고 닫기/검수 동작은 추가하지 않는다.
- 프롬프트 편집의 의상/헤어스타일·해상도·배경 프리셋은 native select로 제공한다. 그 외 옵션은 카드 모달과 hidden input을 유지한다. 기존 입력 ID와 `.value`/change 계약은 동일하게 유지하므로 모델 기본값·지원 옵션·구도·배경 프리셋 처리를 기존 함수와 연결한다. 초안 복원과 키보드 포커스 순환에는 select도 포함한다.
- 후보 전체 썸네일은 제한된 영역 안에서 스크롤한다. PC(769px 이상)에서는 확대 이미지의 우측, 모바일에서는 하단에 배치한다. 썸네일은 정사각형이며 번호 오버레이를 없애고 선택된 후보에만 체크 표시를 제공한다. 확대 중 테두리와 선택 체크는 별개다. 후보 번호는 접근성 라벨·상단 상태·번호 직접 이동에 유지한다. 썸네일은 확대만 변경하고 확대 화면의 선택 버튼으로만 후보를 선택한다. 번호 이동·방향키·스와이프를 제공한다. 최종 반영은 별도 확인 후 기존 확정 함수를 실행한다.
- 비교 대상은 현재 프로젝트에 있는 이미지로 한정한다. 프로젝트 폴더에서 시작해 캐릭터 폴더를 연 뒤 이미지 파일을 선택한다. 외부 파일 업로드·다른 프로젝트 목록·프로젝트 바깥으로 나가는 상위 경로는 제공하지 않는다. 비교 기준이 없는 플랜은 후보만 표시하며, 기준이 있는 플랜은 해당 캐릭터의 비교 이미지를 자동으로 적용한다.
- 비교 기준은 프로젝트별 ‘플랜 상황 → 비교 상황’ 관계로 브라우저 localStorage에 기억한다. 예를 들어 A의 ㄱ 플랜에서 ㄴ 상황 이미지를 고르면 B의 ㄱ 플랜을 열 때 B의 ㄴ 이미지를 조회한다. 상황 판별과 파일 탐색은 기존 getPlannerSituationImage 규칙을 사용한다. 상황 ID로 연결하므로 캐릭터별 파일 경로나 확장자를 직접 치환하지 않는다.
- 캐릭터/상황 전환 시 이전 비교 이미지를 먼저 비우고, 현재 캐릭터의 최신 이미지 목록을 조회한다. 해당 이미지가 없거나 기준 상황이 삭제됐거나 조회가 실패하면 안내를 표시하고 다른 캐릭터의 이미지로 대체하지 않는다. 닫힌 모달이나 이전 플랜의 늦은 조회 응답은 무시한다.
- 비교 해제는 현재 플랜 상황의 비교 관계도 삭제한다. 상황에 연결되지 않은 일반 파일은 선택한 파일의 캐릭터에서만 다시 찾으며 다른 캐릭터에 자동 복사하지 않는다. 관계는 현재 브라우저의 프로젝트별 설정이며 서버 플랜·이미지 데이터와 다른 기기에 동기화하지 않는다.
- 비교 모달은 연 캐릭터 폴더만 조회한다. 전체 캐릭터 이미지 일괄 조회와 다른 프로젝트 조회 로직은 제거했다. 폴더 이동·모달 닫기·프로젝트 전환 시 늦은 응답은 반영하지 않는다.
- 대상 캐릭터·상황 선택 모달도 기존 이미지 편집기 파일 탐색기의 폴더·이미지 카드 스타일을 재사용한다. 캐릭터는 폴더를 연 뒤 ‘이 캐릭터 선택’으로 확정한다. 상황은 캐릭터 폴더 안의 이미지·상황 목록에서 선택하며, 기존처럼 선택한 상황의 전체 캐릭터 플랜을 보여준다. 폴더 경로 탐색은 플래너의 실제 선택 상태를 바꾸지 않는다.
- 모달은 바깥 클릭·닫기·Escape를 지원한다. 실행 확인창은 취소만 제공하며 취소와 별도의 닫기 버튼을 중복하지 않는다. 숨겨진 모달은 키보드 포커스 대상에서 제외한다.
- 개별/일괄 삭제와 개별 재생성의 기존 native confirm도 취소 가능한 공통 확인 모달로 교체한다. 바깥 클릭·Escape·프로젝트 전환은 취소로 해석하며, 실제 삭제·재생성 엔진은 확인 후에만 실행한다.
- 편집 초안은 프로젝트/캐릭터/상황별 메모리에 보관하며 닫았다 열어도 복원한다. 저장 후 초안 제거, 프로젝트 전환 시 초안·비교 이미지 상태를 제거한다. 영구 자동 저장은 아니다.

## 코드 경계 및 레거시 처리

| 대상 | 처리 |
| --- | --- |
| 생성·저장·확정·취소·일시정지·재개·복구·비용·ETA | `planner.js`의 기존 엔진과 API 계약 유지 |
| 3탭 화면/중복 planRows/resultView | 제거하고 메인 그리드 + 실행 화면으로 통합 |
| `renderPlannerImages`, `renderPlannerResultList` | 사용되지 않는 중복 결과 UI 제거 |
| 별도 후보 확대 모달과 PLANNER_IMAGE_PREVIEW 상태 | 통합 검수 화면으로 대체하고 렌더러·열기/닫기·선택 래퍼·호출 제거 |
| 이전 인라인 항목 편집 렌더러/V4 렌더러/추가·삭제 핸들러 | 참조 확인 후 제거. 상황 편집 모달의 V4 처리는 유지 |
| `readPlannerEditsFromDom` | `preparePlannerSavedItems`로 교체. 존재하지 않는 옛 DOM을 읽지 않고 저장된 프롬프트/V4/횟수를 실행에 사용 |
| `savePlannerDraft`, 옛 dirty 상태, 상황 select setter | 폐기된 UI 진입점과 함께 제거 |
| 공통 설정과 프롬프트 옵션 | 공통 설정은 ID를 유지한 카드 모달. 프롬프트의 의상·해상도·배경만 native select 허용 |
| 프리뷰용 합성 데이터 | 서비스 코드에 복사하지 않음. 실제 플랜/이미지/프로젝트 데이터 사용 |
| 비교·검수·옵션·검색·필터·초안 UI 상태 | 새 `planner-workspace.js`에서 관리. 생성 엔진을 import하지 않아 순환 의존을 추가하지 않음 |
| 프로젝트 모듈 캐시 | project.js/main.js 및 프로젝트 모듈 간 import query를 같은 버전으로 갱신. manage.js가 옛 planner 모듈 인스턴스를 다시 불러오는 경로도 제거 |

복구는 기존과 동일하게 멈춘 백그라운드 작업이고 서버가 복구 가능으로 판정한 경우에만 표시한다. 오류/자동 재시도 상태는 기존 실행 큐와 진행 패널에서 유지하며 상시 오류·재시도 버튼은 추가하지 않는다. 기존 데이터베이스·R2 키·API·백그라운드 작업 스키마는 변경하지 않는다.

## 로컬 검증

프로젝트 지침에 따라 브라우저/E2E/실서비스 요청 없이 수행한다.

- 변경 JavaScript의 `node --check`
- `npm run check:planner-workspace`: 폐기 UI 부재, 입력 계약, import/export 연결, 모듈 버전 일치, BOM 확인
- `git diff --check`, 변경한 텍스트 파일의 UTF-8 BOM 확인

## commit/push 후 Cloudflare에서 확인할 항목

1. 두 기준 모두 전체 그리드·3개 필터·검색·스크롤 위치 유지. 프로젝트/대상 전환 및 빈 상태·조회 실패 표시.
2. 후보 있는 항목은 검수, 없는 항목은 편집. 프롬프트/구도/배경/횟수/해상도/V4 저장 후 값과 편집 화면 유지.
3. 저장하지 않은 편집 초안의 닫기/복원 및 저장 후 새 값 반영. 생성 시 저장된 V4/구도가 유지되는지 확인.
4. 후보 20~100장 스크롤·확대·번호/키보드/스와이프 이동과 선택 상태 분리. 최종 확정의 실제 파일·메타데이터 반영 및 임시 데이터 정리.
5. A의 ㄱ 플랜에서 ㄴ 이미지를 비교로 선택한 뒤 B·C의 ㄱ 플랜에서 각 캐릭터의 ㄴ 이미지로 바뀌는지 확인. ㄱ·ㄷ 플랜의 비교 기준이 독립적인지, 새로고침 후 복원되는지, 이미지 없는 캐릭터에서 A 이미지가 남지 않는지, 비교 해제가 유지되는지 확인. 다른 프로젝트·외부 업로드·프로젝트 상위 이동이 없는지와 대상 선택 모달의 폴더 탐색·등급 필터·확정/취소도 확인.
6. PC/320px 모바일/짧은 화면/키보드 표시/다크 모드에서 모달 내부 높이·이미지 비교·프롬프트 편집·작업 버튼 접근 확인.
7. 모든 모달 바깥 클릭·Escape·키보드 포커스 순환·옵션 변경. V5 미지원 옵션 숨김 및 모델 전환 기본값 반영.
8. 브라우저/백그라운드 실행·비용·중단·재개·취소·조건부 복구·오류/자동 재시도 표시. 중복 클릭과 느린 요청/대상 전환 시 늦은 응답 확인.

실제 브라우저 및 Cloudflare 동작 검증은 사용자 commit/push 후 진행해야 한다.
