# AI 이미지 편집기 설계 계약

작성일: 2026-11-17  
구현 기준: 새 편집기 v1 / 기존 편집 문서·API 호환 없음  
연결 문서: [UI 명세](image-editor-ui-spec.md), [구현 및 검증 기록](image-editor-implementation-status.md)

## 1. 규격과 작업 흐름

| 항목 | 확정 정책 |
| --- | --- |
| 원본·추가 이미지 | 1216×832, 1024×1024, 832×1216만 허용. decode 후 실측 크기 검증 |
| 편집 문서·결과 출력 | 위 세 규격만 사용. 임의 크기나 업스케일 없음 |
| 내부 자산 | 마스크·도형·부분 픽셀·192×192 미리보기는 필요한 크기 허용. 각 변 최대 1216 |
| 포함 | 전체 내용이 보이도록 균일 배율로 맞추고 중앙 배치. 남은 부분은 투명 |
| 채우기 | 프리셋을 채우도록 균일 배율로 맞추고 넘친 부분은 출력에서 숨김 |
| 크롭 | 드래그한 영역을 선택한 프리셋에 맞춤. 레이어를 잘라 버리지 않고 행렬 변경 |
| 회전 | 가로↔세로 프리셋 전환과 90° 회전. 정사각은 같은 규격 유지 |
| 원본 보존 | `originalAssetId`는 원본 비교용 불변 자산. 레이어 병합·삭제와 독립적으로 보관 |

예: 1216×832를 1024×1024에 포함하면 약 1024×701로 배치한다. 채우면 약 1497×1024로 배치하고 좌우가 숨겨진다. 배치 크기는 변형값이며 새로운 고해상도 자산을 만드는 기능이 아니다.

핵심 흐름은 이미지 열기 → 선택 → 마스크/수동 보정/AI 수정 → 레이어 합성 → 작업 저장 → 재열기 → 결과 출력이다. 작업 저장과 결과 이미지 저장은 별도 명령이다.

## 2. 문서·런타임·보기 상태

```json
{
  "schemaVersion": 1,
  "id": "document-uuid",
  "projectId": "project-id",
  "prefix": "project/",
  "title": "캐릭터 합성",
  "preset": "square",
  "width": 1024,
  "height": 1024,
  "sourceKey": "project/original.png",
  "originalAssetId": "original-asset-uuid",
  "assets": {
    "original-asset-uuid": {
      "hash": "SHA256_HEX_64",
      "width": 1024,
      "height": 1024,
      "type": "image/png"
    }
  },
  "layers": [],
  "candidates": [],
  "background": "transparent"
}
```

예제의 해시 문자열은 설명용 자리표시자다. 실제 데이터는 소문자 16진수 64자다.

레이어 종류는 image / paint / text / shape / adjustment / group / path다.

문서는 JSON만 포함한다. Canvas·ImageBitmap·Worker·DOM·pointer 세션·복구 요청 객체는 직렬화하지 않는다. 레이어는 `id`, `parentId`, 크기, 6개 요소 행렬, 표시/잠금/알파 잠금, 불투명도, 혼합, mask, effects, style, data를 가진다. 평탄한 배열의 같은 parentId끼리 아래에서 위로 합성한다. 그룹 순환·중복 ID·배율 0·지원 밖 규격은 거부한다.

`stateId`는 클라이언트 내용 상태이고 `savedId`와 같으면 저장된 내용이다. 서버 `revision`은 독립적인 UUID다. Undo로 저장 시점에 돌아오면 dirty가 해제된다. 서버 저장 도중 새로 바뀐 내용은 이전 응답이 dirty를 해제하지 않는다.

현재 도구·줌·패널·레이어 선택·작업 선택 영역·후보 미리보기는 보기 상태다. 후보 보관과 실제 레이어 추가는 문서 변경이며 이력과 저장 대상이다. 미리보기만 바꾸는 것은 문서를 수정하지 않는다.

## 3. 좌표와 마스크

- 화면 좌표 → viewport pan/zoom 역변환 → 문서 좌표 → 그룹을 포함한 worldMatrix 역변환 → 레이어 좌표를 사용한다.
- 선택 영역은 문서 크기의 alpha mask다. `null`은 선택 제한 없음이고, alpha가 모두 0인 캔버스는 빈 선택이다.
- 마스크는 흰색 RGB와 alpha로 표현한다. 흰색 50% alpha는 50% 통과다. 검정 RGB도 alpha가 1이면 통과하므로 RGB만 보고 판단하지 않는다.
- 연결된 레이어 마스크는 레이어 행렬과 원근/워프를 따른다. 분리한 마스크는 문서 기준 행렬을 보관한다.
- 벡터 마스크는 레이어 로컬 좌표의 베지어 앵커·제어점을 JSON으로 보관하고 렌더 때 래스터화한다. 일반 마스크와 동시에 적용할 수 있고 펜으로 재편집한다.
- 선택→마스크는 worldMatrix 역변환으로 샘플링한다. 마스크→선택은 worldMask를 사용한다.
- 프리셋 변경은 루트 레이어 행렬과 분리 마스크 행렬에 동일한 문서 변환을 적용한다. 선택 영역도 같은 문서 변환을 따른다.
- AI 제공자에는 alpha를 불투명 흑백 RGB로 변환한다. 흰색은 다시 생성할 영역, 검정은 유지할 영역이다. 결과를 적용할 때 요청 당시 alpha mask로 다시 제한한다.

예: 빨간 레이어에 50% 마스크와 50% 레이어 불투명도를 사용하면 그 레이어 기여도는 25%다. 선택 경계의 alpha는 브러시 합성에도 곱한다.

## 4. 합성 순서와 이력

일반 레이어는 원본/재편집 가능한 텍스트·도형·패스 → 효과 배열 → 원근/워프 → 스타일 → worldMatrix 배치 → 마스크 → 클리핑 → 불투명도·혼합 순서다. 그룹은 자식을 별도 화면에 합성한 뒤 그룹 효과·스타일·마스크·불투명도·혼합을 적용한다. 그룹은 격리 합성이며 Photoshop의 pass-through 그룹을 별도로 제공하지 않는다.

클리핑은 같은 부모의 바로 아래 비클리핑 레이어 alpha를 기준으로 한다. 기준 레이어가 숨겨졌거나 없으면 클립 결과도 보이지 않는다. 조정 레이어는 앞서 합성한 RGB를 보정하고, 원래 alpha를 보존하면서 마스크×불투명도×클립 영역으로 보간한다. 내보내기는 이 합성기를 쓰고 선택 테두리·가이드·커서는 제외한다.

구조·속성 변경은 이전/이후 JSON, 픽셀 획은 변경 사각형의 이전/이후 ImageData로 기록한다. 변형은 미리보기 뒤 Enter/적용으로 한 명령, Esc/취소로 원복한다. 선택 도구·도구 옵션 변경은 픽셀 이력을 만들지 않는다. 커브 점 드래그·속성 입력도 확정 시 한 명령이다. 이력 예산은 문서당 96MiB이고 최소 최근 한 명령은 유지한다. 이력·AI 요청 스냅샷이 참조한 자산은 런타임 수거에서 제외한다.

## 5. 저장 API와 서비스 경계

관리자 인증을 통과한 `/api/editor`만 내부 편집 자산에 접근한다. R2 바인딩은 `imgBucket`, D1 바인딩은 `DB`다. 기존 생성·구독·가격 모듈은 서비스 계약으로 사용하며 구 편집기 코드는 사용하지 않는다.

| 메서드·경로 | 역할 |
| --- | --- |
| PUT /assets/{sha256} | PNG 내용 해시·실측 헤더 크기 검증 후 불변 업로드 |
| GET·HEAD /assets/{sha256} | 관리자용 자산 읽기, private/no-store |
| GET /documents?projectId=… | 최근 작업 목록 |
| PUT /documents/{id} | document, baseRevision, requestId로 새 revision 저장 |
| GET /documents/{id}?revision=… | 최신/과거 문서 조회 |
| DELETE /documents/{id} | head에 삭제 표시. 공유 자산 실제 삭제 없음 |
| GET /documents/{id}/versions | 확정 버전 목록 |
| GET /documents/{id}/preview | 최근 작업 썸네일 |
| POST /documents/{id}/export | 저장 revision과 출력 규격 확인 후 프로젝트 결과 저장 |
| POST /documents/{id}/repair | operationId에 해당하는 출력 메타데이터 복구 |

요청 JSON은 2MiB, PNG 자산·출력은 각각 8MiB로 제한한다. 자산 최대 600개, 레이어 최대 200개, 후보 최대 100개다. 출력은 PNG/JPEG/WebP이며 JPEG는 선택한 배경으로 투명 부분을 채운다.

R2 `__editor/assets/{hash}.png`는 불변 자산이다. `documents/{id}/versions/{requestId}.json` manifest도 불변이다. `head.json`을 ETag 조건부 갱신한 시점에 revision을 확정한다. D1은 목록과 버전 영수증을 유지하고 head 조회·재시도에서 맞춘다. R2와 D1을 하나의 원자적 트랜잭션으로 취급하지 않는다.

| 상황 | 처리 |
| --- | --- |
| 자산 업로드 실패 | 문서 head 유지, 로컬 복구본 보존, 저장 재시도 |
| 같은 requestId 재시도 | 같은 manifest면 확정 결과 재사용, 다른 내용이면 409 |
| baseRevision/ETag 불일치 | 409, 자동 덮어쓰기 없음. 복제 저장 또는 다시 열기 |
| head 확정 뒤 D1 실패 | 같은 요청 재시도에서 head를 기준으로 목록·영수증 정합성 복구 |
| 출력 이름 충돌 | 현재 ETag를 표시한 확인 화면, 확인한 대상만 백업 후 조건부 갱신 |
| 출력 이미지 성공·메타데이터 실패 | 출력 작업 기록 유지, 복구 버튼 제공, 대상 ETag/해시 재확인 |

자동 저장은 변경 후 2초, 연속 변경은 최대 15초 대기다. 확정하지 않은 변형·획·속성 입력을 저장하지 않는다. IndexedDB 복구를 먼저 시도하고 서버에 업로드한다. 로컬과 서버 실패는 각각 표시한다. 오래된 복구본과 서버 버전이 충돌하면 조용히 서버에 덮어쓰지 않는다.

원본 생성 메타데이터는 최초 작업 저장 시 별도 스냅샷으로 보관한다. 결과 저장은 원본 관계·편집 문서 ID·revision·편집 시간을 기록한다. 덮어쓰기 시 대상 이미지·메타데이터를 내부 경로에 먼저 백업한다. 새 내부 경로는 공개 이미지 서빙·일반 목록·게스트 접근에서 제외한다. 구 데이터 경로의 비공개 보호도 유지한다.

마이그레이션은 `migrations/0027_editor_workspace.sql`이다. 신규 테이블 생성만 수행한다. API에는 같은 IF NOT EXISTS 초기화도 있으며 구 DB·R2 데이터를 삭제하거나 이전하지 않는다. 기존 migration 적용 순서와 배포 환경은 사용자 push 후 확인한다.

## 6. AI 요청과 자동 분리

인페인트는 기존 `/api/generate`에 `action: infill`을 보내고 현재 서비스 모델 프로필·가격 계산을 사용한다. 한 요청은 후보 한 장이며 1~8회를 순차 실행한다. 각 요청 전 구독/비용을 갱신하고 표시한 상한보다 높아지면 다음 요청을 중단한다. 실패한 요청을 과금 가능성이 있는 상태에서 자동 반복하지 않는다.

요청 때 문서 ID·revision·내용 상태·입력 이미지·마스크·설정과 레이어/픽셀의 불변 복사본을 확보한다. 생성 중 편집해도 결과가 최신 레이어를 자동 수정하지 않는다. 결과 크기가 계약과 다르면 거부한다. 후보는 원래 문서에 보관하고 명시적으로 레이어 추가한다. 규격이 달라졌으면 `요청 당시 작업 열기`로 당시 레이어를 복제한 별도 문서에서 적용한다.

결과 수신 중단은 fetch 대기 중단이다. 제공자의 실행 중지나 Anlas 환급을 보장하지 않는다. 실제 생성·과금 검증은 별도 배포 확인 항목이다.

자동 피사체 선택은 별도 module Worker에서 Transformers.js 3.8.1과 Xenova/MODNet FP32 WASM을 로드한다. 원본 픽셀은 Worker로 전달하고 모델 추론을 기기에서 수행한다. 최초 사용에는 CDN·모델 파일 다운로드와 모델 준비 시간이 발생한다. RGBA 결과의 alpha를 선택 영역으로 사용하고 적용 전 사용자가 확인한다. 배경색 자동 선택은 모델 추론과 구분한 별도 명령이다. 애니메이션 캐릭터·복수 인물·머리카락의 실제 분리 품질은 배포 검증 대상이다.
