# 플래너 캐릭터·상황 기준 일괄 생성 구현 계획

작성일: 2026-08-10

## 1. 목적

플래너의 플랜 작성 화면에 다음 두 가지 작성 기준을 제공한다.

- **캐릭터 기준**: 캐릭터 한 명을 선택하고, 그 캐릭터에게 필요한 여러 상황의 플랜을 일괄 생성한다.
- **상황 기준**: 상황 하나를 선택하고, 그 상황에 필요한 여러 캐릭터의 플랜을 일괄 생성한다.

두 기준 모두 생성 대상은 아래 조건을 동시에 만족하는 `캐릭터 × 상황` 조합으로 제한한다.

```text
플랜이 없음 AND 최종 이미지가 없음
```

이미 플랜이 있거나 최종 이미지가 있는 조합은 수정하거나 덮어쓰지 않는다. 기존 플랜의 세부 수정, 재생성, 이미지 교체 등은 사용자가 개별 기능을 통해 직접 처리한다.

## 2. 범위

### 2.1 포함 범위

1. `플랜짜기` 화면에 `캐릭터 기준 | 상황 기준` 전환 UI를 추가한다.
2. 현재 선택된 기준을 사용자가 즉시 구분할 수 있도록 선택 상태와 화면 문맥을 함께 변경한다.
3. 캐릭터 기준에서는 기존 상황 카드 목록을 유지한다.
4. 상황 기준에서는 선택한 상황에 대한 캐릭터 카드 목록을 표시한다.
5. 두 기준 모두 `누락된 플랜 전체 생성` 버튼을 사용한다.
6. 상황 기준 일괄 플랜 생성 로직을 추가한다.
7. 기존 플랜과 최종 이미지가 없는 조합만 생성한다.
8. 처리 결과를 생성·제외·실패 건수로 안내한다.

### 2.2 제외 범위

1. 기준에 따라 생성 버튼 문구를 동적으로 변경하지 않는다.
2. 기존 플랜을 일괄 덮어쓰거나 갱신하지 않는다.
3. 최종 이미지가 있는 조합의 플랜을 자동으로 다시 만들지 않는다.
4. 일괄 생성 화면에서 캐릭터별 프롬프트를 직접 편집하지 않는다.
5. 이미지 생성 실행 방식과 실행 화면은 변경하지 않는다.
6. 다중 캐릭터 선택, 다중 상황 선택 기능은 이번 범위에 포함하지 않는다.
7. 서버 데이터 스키마와 플랜 식별자 구조는 변경하지 않는다.

## 3. 핵심 용어와 동작 기준

### 3.1 캐릭터 기준

```text
선택 대상: 캐릭터 1명
목록 축: 전체 상황
일괄 생성 대상: 선택한 캐릭터 × 플랜과 이미지가 모두 없는 상황
```

기존 `createMissingPlannerPlans()`의 역할을 유지하되, 버튼 명칭과 공통 판정 helper를 새 기준에 맞게 정리한다.

### 3.2 상황 기준

```text
선택 대상: 상황 1개
목록 축: 전체 캐릭터
일괄 생성 대상: 선택한 상황 × 플랜과 이미지가 모두 없는 캐릭터
```

캐릭터별 기본 프롬프트, 활성 캐릭터 프롬프트 variant, 공통 플래너 설정, 프로젝트 스타일 및 배경 설정을 사용하여 각 캐릭터의 플랜 item을 만든다.

### 3.3 생성 대상 판정표

| 기존 플랜 | 최종 이미지 | 처리 |
| --- | --- | --- |
| 없음 | 없음 | 새 플랜 생성 |
| 있음 | 없음 | 제외: 기존 플랜 보존 |
| 없음 | 있음 | 제외: 완성 이미지 보존 |
| 있음 | 있음 | 제외: 기존 데이터 보존 |

후보 이미지나 임시 생성 결과가 있는 실행 중 플랜은 이미 `기존 플랜 있음`에 해당하므로 새 플랜을 만들지 않는다.

## 4. UI 구조

### 4.1 기준 전환 UI 위치

`플랜짜기 / 실행 화면 / 결과 확인` 상위 탭 아래, 플랜짜기 본문 툴바 위에 다음 영역을 추가한다.

```text
[플랜짜기] [실행 화면] [결과 확인]

플랜 작성 기준
[캐릭터 기준] [상황 기준]

대상 선택기 / 안내 문구 / 누락된 플랜 전체 생성
목록
```

상위 탭은 플래너 작업 단계이고, 새 기준 전환은 `플랜짜기` 내부에서 목록을 바라보는 방향이다. 따라서 두 종류의 탭을 같은 줄에 섞지 않는다.

### 4.2 현재 기준을 명확하게 표시하는 규칙

현재 기준은 색상 하나만으로 구분하지 않고 다음 단서를 동시에 제공한다.

1. 선택된 기준 버튼은 인디고 배경과 흰색 텍스트로 표시한다.
2. 선택되지 않은 기준 버튼은 테두리형으로 표시한다.
3. 선택 버튼에 `aria-selected="true"`를 적용한다.
4. 영역 제목으로 `플랜 작성 기준`을 항상 표시한다.
5. 대상 선택기 라벨을 기준에 맞게 표시한다.
   - 캐릭터 기준: `대상 캐릭터`
   - 상황 기준: `대상 상황`
6. 목록 위 안내 문구를 기준에 맞게 표시한다.
   - 캐릭터 기준: `선택한 캐릭터의 상황별 플랜을 관리합니다.`
   - 상황 기준: `선택한 상황의 캐릭터별 플랜을 관리합니다.`
7. 본문 목록 자체도 기준에 따라 상황 카드 또는 캐릭터 카드로 전환한다.

이 중 하나만 보더라도 현재 기준을 알 수 있고, 전체 화면 문맥도 서로 모순되지 않아야 한다.

### 4.3 기본값과 상태 수명

- 최초 진입 기본값은 기존 동작을 보존하는 `캐릭터 기준`이다.
- 같은 플래너 화면 안에서 다시 렌더링될 때는 선택한 기준을 유지한다.
- 프로젝트를 바꾸거나 페이지를 새로 연 경우에는 `캐릭터 기준`으로 초기화한다.
- 이번 단계에서는 localStorage에 장기 저장하지 않는다. 이전 방문의 상황 기준이 다음 방문에 자동 적용되어 사용자가 범위를 오인하는 것을 방지한다.

### 4.4 버튼 구성

두 기준 모두 같은 버튼 문구를 사용한다.

```text
누락된 플랜 전체 생성
```

버튼 문구는 동적으로 바꾸지 않는다. 대신 바로 앞의 기준 전환 UI, 대상 선택기 라벨, 안내 문구로 실행 범위를 명확히 전달한다.

### 4.5 캐릭터 기준 화면

- `대상 캐릭터` 선택기를 표시한다.
- 현재의 상황 카드 그리드를 유지한다.
- 상황 카드에는 최종 이미지와 플랜 유무를 현재와 같은 방식으로 표시한다.
- 상황 카드를 누르면 현재의 개별 상황 플랜 편집 모달을 연다.
- `누락된 플랜 전체 생성`은 선택된 캐릭터에 대해서만 동작한다.

### 4.6 상황 기준 화면

- `대상 상황` 선택기를 표시한다.
- 선택한 상황에 대한 캐릭터 카드 그리드를 표시한다.
- 캐릭터 카드에는 최소한 다음 상태 중 하나를 텍스트로 표시한다.
  - `생성 대상`: 플랜 없음, 이미지 없음
  - `플랜 있음`: 기존 플랜 보존
  - `이미지 있음`: 최종 이미지 보존
  - `확인 필요`: 캐릭터 정보 로드 실패 등으로 판정 불가
- 카드를 선택하거나 편집하는 기능은 이번 범위에 넣지 않는다. 카드는 대상과 제외 이유를 확인하는 표시용으로 사용한다.
- `누락된 플랜 전체 생성`은 `생성 대상` 상태의 캐릭터에 대해서만 동작한다.

### 4.7 실행 전후 안내

버튼 실행 전 별도 옵션 모달은 추가하지 않는다. 동작이 비파괴적이고 생성 조건이 단순하기 때문이다.

버튼 실행 후 `planner-status`에 다음 정보를 표시한다.

```text
3개 플랜을 생성했습니다. 기존 플랜 2개, 완성 이미지 1개는 보존했습니다.
```

일부 저장이 실패한 경우 성공 항목을 되돌리지 않고 다음처럼 안내한다.

```text
3개 플랜을 생성했고 1개는 저장하지 못했습니다. 기존 항목은 변경하지 않았습니다.
```

## 5. 프론트엔드 상태 설계

`public/js/project/planner.js`에 플랜 작성 기준 상태를 추가한다.

```text
window.PROJECT_PLANNER_PLAN_SCOPE = 'character' | 'situation'
```

초기값은 `character`로 한다.

상황 기준에서 선택한 상황은 별도 상태로 관리한다.

```text
window.PROJECT_PLANNER_SELECTED_SITUATION_ID
```

선택 상황이 없거나 삭제된 경우 프로젝트의 첫 번째 상황을 fallback으로 사용한다. 캐릭터 기준에서 사용하는 기존 선택 캐릭터 상태는 그대로 유지한다.

기준을 전환할 때 다음 상태는 변경하지 않는다.

- 현재 선택된 캐릭터
- 현재 선택된 상황
- 저장된 플랜 meta
- 실행 및 결과 화면 상태

따라서 사용자가 기준을 왕복해도 직전에 보던 대상을 다시 확인할 수 있다.

## 6. 코드 변경 계획

### 6.1 기준 상태와 이벤트 추가

대상: `public/js/project/planner.js`

1. `getPlannerPlanScope()` helper를 추가하고 허용되지 않은 값은 `character`로 정규화한다.
2. `setPlannerPlanScope(scope)` 이벤트를 추가한다.
3. 기준 전환 시 플랜 본문을 다시 렌더링한다.
4. 선택된 기준 버튼의 시각 상태와 `aria-selected`를 동기화한다.
5. `window` 이벤트 export 구간에 새 이벤트를 연결한다.

### 6.2 대상 선택기 분기

대상: `renderPlannerPanel()`

1. 기존 `characterSelector`를 캐릭터 기준에서 계속 사용한다.
2. 상황 기준용 `situationSelector`를 추가한다.
3. 현재 기준에 따라 선택기 라벨과 option 목록을 바꾼다.
4. 상황 선택 변경 시 선택 상황 ID를 갱신하고 본문만 다시 렌더링한다.
5. 설정 및 새로고침 버튼 위치는 유지한다.

### 6.3 기준 전환 영역 추가

대상: `renderPlannerPanel()`의 `planView`

1. 기존 플랜짜기 툴바 위에 `플랜 작성 기준` 영역을 렌더링한다.
2. `캐릭터 기준`, `상황 기준`을 하나의 segmented control로 표시한다.
3. 버튼의 텍스트, 선택 스타일, `aria-selected`를 함께 갱신한다.
4. 기존 `누락 이미지 플랜 생성` 문구를 `누락된 플랜 전체 생성`으로 변경한다.
5. 기준별로 버튼 handler만 분기하고 버튼 문구는 유지한다.

### 6.4 상황 기준 캐릭터 그리드 추가

대상: `public/js/project/planner.js`

신규 렌더러 예시:

```text
renderPlannerCharacterGridForSituation(project, characters, situation, metas)
```

처리 순서:

1. 캐릭터별 최종 이미지 존재 여부를 확인한다.
2. 캐릭터별 planner meta에서 선택 상황의 item 존재 여부를 확인한다.
3. 공통 판정 helper로 상태를 계산한다.
4. 캐릭터 카드에 이름과 판정 상태를 표시한다.
5. 판정에 필요한 데이터가 아직 없으면 `확인 필요`로 표시하고 일괄 생성 대상에서 제외한다.

### 6.5 공통 생성 대상 판정 helper 추가

캐릭터 기준과 상황 기준이 서로 다른 판정 규칙을 갖지 않도록 하나의 helper를 사용한다.

개념적인 입력과 출력은 다음과 같다.

```text
입력:
- character
- situation
- situationIndex
- plannerMeta

출력:
- hasPlan
- hasFinalImage
- eligible = !hasPlan && !hasFinalImage
- reason
```

최종 이미지는 기존 `getPlannerSituationImage()`을 사용해 판정하고, 플랜은 기존 `getPlannerSituationItem()`을 사용해 판정한다.

### 6.6 기존 캐릭터 기준 일괄 생성 정리

대상: `createMissingPlannerPlans()`

1. 함수 이름은 호환을 위해 유지하거나 `createAllMissingPlannerPlansForCharacter()`로 분리한 뒤 기존 export가 이를 호출하게 한다.
2. 신규 공통 판정 helper를 사용한다.
3. 생성 조건을 `플랜 없음 AND 최종 이미지 없음`으로 명시한다.
4. 기존 플랜과 이미지는 그대로 보존한다.
5. 성공·제외 건수를 상태 메시지에 반영한다.

현재 함수도 동일한 핵심 조건을 사용하지만, 상황 기준과 규칙이 달라지지 않도록 판정 부분을 공통화한다.

### 6.7 상황 기준 일괄 생성 함수 추가

신규 함수 예시:

```text
createAllMissingPlannerPlansForSituation(situationId)
```

처리 순서:

1. 활성 프로젝트와 선택 상황을 확인한다.
2. 프로젝트의 전체 캐릭터를 가져온다.
3. 캐릭터별 파일 목록, 캐릭터 meta, planner meta를 불러온다.
4. 공통 helper로 각 `캐릭터 × 선택 상황`을 판정한다.
5. 생성 대상이 아닌 항목은 이유별 개수만 집계하고 변경하지 않는다.
6. 생성 대상마다 기존 `buildPlannerPlanItemFromSituation()`을 호출한다.
7. 해당 캐릭터의 기존 meta가 있으면 다른 item을 유지한 채 새 item 하나만 추가한다.
8. meta가 없으면 현재 compact run 계약에 맞는 새 meta를 만든다.
9. `savePlannerItem()` 또는 기존 저장 helper를 이용해 캐릭터별 item을 저장한다.
10. 저장 성공 시 meta cache와 queue meta cache를 갱신한다.
11. 현재 선택된 캐릭터의 meta가 변경된 경우 `window.PROJECT_PLANNER_META`도 동기화한다.
12. 전체 결과를 집계해 상태 메시지를 표시하고 화면을 다시 렌더링한다.

한 캐릭터의 실패가 다른 캐릭터 저장을 막지 않도록 캐릭터별로 오류를 수집한다. 동시 저장 충돌과 과도한 API 요청을 피하기 위해 무제한 `Promise.all()` 대신 순차 처리 또는 작은 동시성 제한을 사용한다.

### 6.8 일괄 생성 dispatcher 추가

UI 버튼은 하나의 handler를 호출한다.

```text
createAllMissingPlannerPlans()
```

handler는 현재 기준에 따라 다음으로 분기한다.

```text
character -> 캐릭터 기준 일괄 생성
situation -> 상황 기준 일괄 생성
```

버튼 markup에 서로 다른 handler를 직접 넣지 않아 렌더링 조건과 실제 실행 범위가 어긋나는 것을 방지한다.

## 7. 서버와 데이터 저장 영향

현재 compact planner run은 프로젝트와 캐릭터 단위로 저장되고, 각 run 안에 상황별 item이 포함된다. 상황 기준 일괄 생성도 새로운 상황 중심 record를 만들지 않고 기존 캐릭터별 run에 item을 하나씩 추가한다.

따라서 이번 수정에서는 다음 변경이 필요하지 않다.

- D1 migration
- 신규 record type
- 상황 중심 planner run
- 플랜 ID 생성 규칙 변경
- 이미지 생성 API 변경

상황 기준은 프론트엔드에서 여러 캐릭터별 저장 요청을 조정하는 기능으로 구현한다.

## 8. 충돌 및 예외 처리

### 8.1 저장 직전 재검증

상황 기준 목록을 렌더링한 뒤 다른 작업이 플랜을 추가했을 수 있다. 각 캐릭터를 저장하기 직전에 최신 planner meta를 다시 확인하거나, `savePlannerItem()`의 revision conflict 응답을 처리한다.

409 충돌이 발생하면 다음 원칙을 적용한다.

1. 최신 meta를 다시 불러온다.
2. 대상 상황의 플랜 또는 이미지가 새로 생겼는지 다시 판정한다.
3. 이미 존재하면 정상 제외로 처리한다.
4. 여전히 생성 대상이면 한 번만 재시도한다.
5. 재시도도 실패하면 해당 캐릭터만 실패로 기록한다.

### 8.2 데이터 로드 실패

캐릭터 파일 또는 meta를 읽지 못하면 이미지 부재로 단정하지 않는다. 해당 캐릭터를 `확인 필요`로 분류하고 생성 대상에서 제외한다.

### 8.3 생성 가능한 항목이 없는 경우

저장 요청을 보내지 않고 다음처럼 안내한다.

```text
새로 만들 누락 플랜이 없습니다. 기존 플랜과 이미지는 변경하지 않았습니다.
```

### 8.4 실행 중 상태

실행 중인 run에는 이미 대상 플랜 item이 존재하므로 공통 판정에서 제외된다. 실행 중이라는 이유로 다른 캐릭터의 정상적인 신규 플랜 생성까지 전체 차단하지 않는다.

## 9. 접근성 및 반응형 기준

1. 기준 전환은 native `button`을 사용한다.
2. 전환 그룹에 적절한 `role="tablist"` 또는 동일 의미의 접근 가능한 구조를 사용한다.
3. 선택 상태를 `aria-selected`로 제공한다.
4. 선택 여부를 색상뿐 아니라 텍스트 위치와 화면 문맥으로 전달한다.
5. 키보드로 두 기준 버튼에 접근하고 실행할 수 있어야 한다.
6. 좁은 화면에서는 기준 버튼이 동일 너비로 한 줄을 채우게 한다.
7. 대상 선택기는 좁은 화면에서 전체 너비를 사용한다.
8. 카드 상태는 색상 badge만 사용하지 않고 상태 텍스트를 함께 표시한다.

## 11. 검증 계획

프로젝트 규칙에 따라 로컬에서는 브라우저·E2E·live service 테스트를 수행하지 않고 정적 검사만 수행한다.

### 11.1 로컬 정적 검사

1. `node --check public/js/project/planner.js`
2. 신규 handler의 `window` 연결 누락 검색
3. 캐릭터 기준과 상황 기준 모두 공통 판정 helper를 사용하는지 확인
4. 기존 플랜 또는 이미지가 있는 경우 저장 helper가 호출되지 않는지 코드 경로 확인
5. 수정한 텍스트 파일의 시작 bytes가 UTF-8 BOM `EF BB BF`가 아닌지 확인

### 11.2 Cloudflare 배포 후 확인 시나리오

1. 플래너 최초 진입 시 `캐릭터 기준`이 선택되어 있다.
2. 선택된 기준이 배경·텍스트·`aria-selected`로 명확히 구분된다.
3. 상황 기준으로 전환하면 대상 선택기가 `대상 상황`으로 바뀐다.
4. 캐릭터 기준으로 돌아오면 이전에 선택했던 캐릭터가 유지된다.
5. 상황 기준으로 다시 이동하면 이전에 선택했던 상황이 유지된다.
6. 캐릭터 기준에서 플랜과 이미지가 모두 없는 상황만 생성된다.
7. 상황 기준에서 플랜과 이미지가 모두 없는 캐릭터만 생성된다.
8. 플랜만 있는 조합은 변경되지 않는다.
9. 이미지만 있는 조합은 변경되지 않는다.
10. 플랜과 이미지가 모두 있는 조합은 변경되지 않는다.
11. 한 캐릭터 저장이 실패해도 다른 캐릭터의 성공 결과는 유지된다.
12. 실행 직전 다른 요청이 플랜을 만든 경우 기존 플랜이 덮어써지지 않는다.
13. 생성 대상이 0개이면 저장 요청 없이 안내 메시지만 표시된다.
14. 생성 후 캐릭터 기준과 상황 기준 양쪽 목록에 동일한 상태가 반영된다.
15. 실행 화면과 결과 확인 화면의 기존 동작에는 변화가 없다.

## 12. 완료 기준

다음 조건을 모두 만족하면 구현이 완료된 것으로 본다.

- 플랜짜기 화면에서 캐릭터 기준과 상황 기준을 전환할 수 있다.
- 현재 선택된 기준을 색상 외의 텍스트와 화면 문맥으로도 명확히 알 수 있다.
- 기본값은 캐릭터 기준이며 기존 플래너 동작을 유지한다.
- 두 기준 모두 `누락된 플랜 전체 생성` 버튼을 사용한다.
- 캐릭터 기준은 선택 캐릭터의 누락 상황만 생성한다.
- 상황 기준은 선택 상황의 누락 캐릭터만 생성한다.
- 생성 조건은 항상 `플랜 없음 AND 최종 이미지 없음`이다.
- 기존 플랜과 기존 최종 이미지는 수정하거나 덮어쓰지 않는다.
- 상황 기준 생성은 기존 캐릭터별 compact run 저장 구조를 재사용한다.
- 일부 대상 실패가 전체 작업 실패로 확대되지 않는다.
- 로컬 정적 검사와 UTF-8 BOM 검사를 통과한다.
- Cloudflare 배포 후 필수 시나리오를 확인한다.
