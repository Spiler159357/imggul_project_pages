# 이미지 경로 변경 모달 간단 명세

## 1. 목적

이미지 확인 모달의 `경로명`과 `이동` 버튼을 `경로 변경` 버튼 하나로 통합한다.

사용자는 절대경로를 직접 입력하지 않고 프로젝트 내부 폴더를 탐색해 대상 폴더를 선택하고, 같은 화면에서 파일명도 변경할 수 있어야 한다.

이 모달은 저장소의 실제 파일 경로를 변경하는 기능만 담당한다. 사용자에게 표시되는 `이름`(alias) 변경은 기존 이름 변경 기능으로 분리한다.

## 2. 진입과 종료

- 이미지 확인 모달의 `경로명`, `이동` 버튼을 제거하고 `경로 변경` 버튼 하나를 둔다.
- 버튼을 누르면 이미지 확인 모달 위에 경로 변경 모달을 연다.
- `취소`, 닫기 버튼, `Escape`, 배경 클릭으로 변경 없이 닫는다.
- 닫은 뒤에는 `경로 변경` 버튼으로 포커스를 복원한다.
- 저장 중에는 중복 실행을 막고 임의로 닫히지 않게 한다.

## 3. 화면 구성

### 3.1 헤더

- 제목: `이미지 경로 변경`
- 설명: `프로젝트 안에서 이동할 폴더를 선택하고 파일명을 수정할 수 있습니다.`
- 닫기 버튼

### 3.2 현재 파일 정보

- 이미지 썸네일
- 표시 이름이 있으면 표시 이름
- 현재 파일명
- 프로젝트 기준 현재 상대경로

내부 저장소의 전체 절대경로는 기본 화면에 노출하지 않는다.

### 3.3 대상 폴더 탐색기

- 프로젝트 루트를 최상위로 고정한다.
- 상단에 breadcrumb를 제공해 현재 탐색 위치와 상위 경로를 확인하고 이동할 수 있게 한다.
- 본문에는 현재 위치의 하위 폴더만 표시한다. 이미지와 일반 파일은 목적지 선택에 필요하지 않으므로 기본적으로 숨긴다.
- 폴더를 누르면 해당 폴더 안으로 들어간다.
- `상위 폴더` 동작을 제공하되 프로젝트 루트 밖으로는 나갈 수 없게 한다.
- 현재 보고 있는 폴더를 대상 폴더로 자동 선택한다.
- 하위 폴더가 없을 때도 현재 폴더를 목적지로 선택할 수 있어야 한다.
- 로딩, 빈 폴더, 목록 조회 실패 상태를 각각 표시한다.

### 3.4 파일명 입력

- 현재 파일명을 기본값으로 채운 단일 입력 필드를 제공한다.
- 확장자를 포함한 전체 파일명을 수정할 수 있다.
- 경로 구분자(`/`, `\\`) 입력은 허용하지 않는다.
- 빈 값, `.`/`..`, 제어문자 등 유효하지 않은 파일명은 즉시 안내한다.
- 확장자 변경 시 이미지 형식 또는 처리 방식이 달라질 수 있으므로 경고하거나 1차 구현에서는 기존 확장자 변경을 제한한다.

### 3.5 변경 결과 미리보기

- `현재 경로`와 `변경 후 경로`를 프로젝트 기준 상대경로로 나란히 표시한다.
- 선택 결과에 따라 동작 요약을 표시한다.
  - 폴더만 변경: `이동`
  - 파일명만 변경: `파일명 변경`
  - 둘 다 변경: `이동 + 파일명 변경`
  - 변경 없음: 저장 버튼 비활성화

### 3.6 푸터

- 보조 버튼: `취소`
- 주요 버튼: `변경 적용`
- 주요 버튼은 입력이 유효하고 실제 변경이 있을 때만 활성화한다.

## 4. 필수 기능

1. 프로젝트 내부 폴더 목록 조회 및 단계별 탐색
2. breadcrumb를 통한 상위 경로 이동
3. 대상 폴더 선택
4. 파일명 수정
5. 변경 후 상대경로 실시간 미리보기
6. 동일 경로 여부와 파일명 유효성 검사
7. 대상 경로에 같은 이름의 파일이 있는지 충돌 검사
8. 이동, 파일명 변경, 동시 변경을 한 번의 저장 동작으로 처리
9. 파일 이동과 함께 연결된 메타데이터 경로 갱신
10. 성공 후 탐색기 캐시 무효화 및 현재 목록 새로고침
11. 성공 후 기존 이미지 확인 모달을 닫고 완료 메시지 표시
12. 실패 시 모달과 사용자 입력을 유지하고 원인을 인라인 오류로 표시

## 5. 동작 규칙

- 탐색 가능 범위와 저장 가능 범위는 현재 파일이 속한 최상위 프로젝트 prefix 아래로 제한한다. `window.ROOT_PATH`가 설정된 화면에서는 해당 값을 우선 사용한다.
- 새 경로는 사용자가 절대경로 문자열을 입력해서 만들지 않고, 선택한 폴더 prefix와 파일명으로 조합한다.
- 원본과 대상이 같으면 API를 호출하지 않는다.
- 대상 파일이 이미 존재하면 덮어쓰지 않는다. 충돌 안내 후 다른 파일명 또는 폴더를 선택하게 한다.
- 성공하기 전에는 미리보기 모달의 `currentFileKey`를 변경하지 않는다.
- 서버 파일 이동은 기존 `/api/manage`의 `move` 동작을 사용하고, 성공 후 기존 메타데이터 이동 처리를 이어서 수행한다.
- 서버 작업 일부만 성공할 수 있는 구조라면 파일과 메타데이터의 불일치를 복구할 수 있도록 오류를 구분해 표시한다.

## 6. 권장 반응형 구성

- 데스크톱: 왼쪽에 폴더 탐색기, 오른쪽에 현재 파일 정보·파일명·변경 결과를 배치한다.
- 모바일: 현재 파일 정보, 폴더 탐색기, 파일명, 변경 결과 순서의 단일 열로 배치한다.
- 본문만 스크롤하고 헤더와 푸터는 고정한다.

## 7. 접근성

- 모달에 `role="dialog"`, `aria-modal="true"`, 제목과 설명 연결을 적용한다.
- 열릴 때 현재 대상 폴더 또는 파일명 입력으로 포커스를 이동한다.
- Tab/Shift+Tab 포커스를 모달 내부에 가둔다.
- 폴더 선택 상태, 로딩 상태, 저장 결과를 스크린 리더에 전달한다.
- 폴더 항목과 버튼은 키보드로 탐색하고 실행할 수 있어야 한다.

## 8. 1차 구현 제외 범위

- 새 폴더 생성
- 폴더 이름 변경 및 삭제
- 여러 이미지 일괄 이동
- 프로젝트 밖 또는 다른 프로젝트로 이동
- 파일 덮어쓰기
- 드래그 앤 드롭 이동

## 9. 완료 조건

1. 사용자가 경로 문자열을 직접 입력하지 않고 프로젝트 내부의 임의 폴더를 선택할 수 있다.
2. 한 모달에서 폴더 이동과 파일명 변경을 각각 또는 동시에 수행할 수 있다.
3. 프로젝트 루트 밖으로 이동할 수 없다.
4. 잘못된 파일명과 대상 경로 충돌을 저장 전에 확인할 수 있다.
5. 성공 시 파일과 연결 메타데이터가 새 경로를 사용하고 탐색기 화면이 갱신된다.
6. 실패 시 입력값이 보존되고 재시도할 수 있다.
7. 모바일, 다크 모드, 키보드 조작에서도 주요 기능을 사용할 수 있다.
