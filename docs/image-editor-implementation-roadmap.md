# AI 이미지 편집기 세부 실행 계획

작성일: 2026-11-17  
상태: 신규 구현 반영 / 정적 확인 / Cloudflare 배포 검증 대기  
기준 문서: [AI 생성 이미지 편집기 신규 구축 계획서](image-editor-photoshop-upgrade-plan.md)

## 1. 실행 계획의 기준

이 문서는 상위 계획의 기능과 UI를 실제 구현 묶음으로 나눈 작업 목록이다. UI·문서·저장 계약을 먼저 정하고 새 편집기를 독립적으로 구축한다. 기존 편집기 보수·UI 재사용·구 문서 이전·구 API 호환은 선행 작업에 넣지 않는다.

지원 원본은 1216×832, 1024×1024, 832×1216으로 고정한다. 작업문서·출력도 세 규격으로 운용하는 상위 계획의 기본안을 적용해 세부 작업을 작성했다. 이 출력 정책은 설계 제안이며 0단계에서 정책 문서로 명확히 기록한다. 임의 고해상도·업스케일·대형 캔버스 대응은 작업 목록에 포함하지 않는다.

처음 달성할 제품 목표는 **원본 열기 → 영역 선택 → 수동/AI 수정 → 레이어 합성·부분 보정 → 저장·재열기 → 결과 출력**이다. 전문 리터칭과 자동 분리·다중 문서는 후속 단계로 관리한다.

이 문서는 실행 계획의 기준이다. 실제 구현·정적 확인 결과와 미실행 검증은 [구현 및 검증 기록](image-editor-implementation-status.md)에 구분한다. 설계 계약·UI 시안·신규 코드·SQL을 추가했으며 배포에서의 동작·품질·성능은 아직 검증하지 않았다.

## 2. 전체 단계와 상위 계획의 대응

| 실행 단계 | 목표 | 상위 계획 단계 | 선행 단계 | 단계 종료 시 가능한 작업 |
| --- | --- | --- | --- | --- |
| 0 | 제품 정책·UI·공통 계약 | 0. 제품·UI 설계 | 없음 | 세 규격의 UI와 문서·저장·AI 규칙을 검토 |
| 1 | 새 작업 화면·입력 수명주기 | 1. 새 기반 | 0 | 새 화면에서 도구·패널·상태 전환 |
| 2 | 문서·자산·렌더러·이력 | 1. 새 기반 | 0~1 | 세 규격 이미지 표시·기본 레이어 편집·Undo |
| 3 | 서버 저장·자동 저장·복구 | 1. 새 기반 | 2 | 편집을 저장하고 같은 상태로 재열기 |
| 4 | 레이어·변형·구도 | 2. 선택·합성 | 2~3 | 복수 이미지 배치·그룹·변형·규격 변경 |
| 5 | 선택·마스크·클리핑 | 2. 선택·합성 | 4 | 캐릭터를 분리하고 합성 경계 수정 |
| 6 | 페인팅·색상·조정·필터 | 2~3 | 5 | 직접 수정·국소 색 보정·가림 효과 |
| 7 | 텍스트·도형·기본 스타일 | 3. 첫 실용 릴리스 | 4~6 | 문구·도형·테두리·그림자 재편집 |
| 8 | 인페인트·후보 비교 | 3. 첫 실용 릴리스 | 3·5·6 | 편집 화면에서 AI 부분 수정 |
| 9 | 출력·출시 검증·진입점 교체 | 3. 첫 실용 릴리스 | 0~8 | 새 편집기를 기본 진입점으로 사용 |
| 10 | 전문 편집 도구 | 4. 전문 편집 | 9 | 도장·힐링·정밀 경계·곡선·패스·워프 |
| 11 | 반복 작업·다중 문서·입력 확장 | 5. 효율 확장 | 관련 9~10 작업 | 여러 이미지의 반복 수정·비교·저장 |

실제 구현은 한 묶음씩 진행한다. 표의 선행 단계는 통합 완료 기준이다. 예를 들어 AI 입출력 계약 조사는 0단계에 먼저 하고 실제 편집기 연결은 8단계에 한다. 텍스트·AI의 세부 작업은 각 의존 작업 완료 후 진행할 수 있으나 첫 출시는 9단계의 통합 조건을 모두 만족해야 한다.

```text
0 정책·UI·계약
  → 1 새 화면 → 2 엔진·문서 → 3 저장·복구
  → 4 레이어·변형 → 5 선택·마스크 → 6 보정·페인팅
  → 7 텍스트·표현 / 8 AI 요청·후보
  → 9 출력·통합 검증·교체
  → 10 전문 도구 → 11 반복 작업·효율 확장
```

## 3. 공통 작업 규칙

### 3.1 작업 단위와 완료 기록

- 작업 ID 하나는 한 번에 검토할 수 있는 구현 묶음으로 취급한다. UI·엔진·저장이 크게 섞이면 하위 ID로 나눈다.
- 작업 상태는 미착수 → 진행 중 → 정적 확인 완료 → 배포 확인 완료로 관리한다. 해당 동작을 검증하지 않았는데 완료로 표시하지 않는다.
- 설계 작업은 명세·시안·예제 검토 완료로 종료한다. 실제 동작 증거가 필요한 구현 작업은 Cloudflare 배포 확인을 남긴다.
- 기능을 추가할 때 렌더링뿐 아니라 명령/Undo·직렬화·재열기·UI 상태를 함께 연결한다.
- 기능마다 임의의 저장·좌표·마스크 규칙을 만들지 않는다. 확정된 공통 계약을 사용한다.
- 상위 계획에 없는 해상도·레거시 호환·전문 사진 기능을 작업 도중 추가하지 않는다.

각 작업의 기록은 아래 형식을 사용한다.

```text
작업 ID / 제목 / 상태
변경 파일·산출물
완료한 범위 / 남은 범위
정적 확인 결과
Cloudflare 배포 식별값 / 확인한 규격·시나리오 / 결과
발견 문제 / 다음 작업
```

### 3.2 검증 방식

로컬에서는 구문·import/export·스키마·SQL·참조 관계 검토와 diff·UTF-8 BOM 확인만 한다. 별도 요청 없이 로컬 브라우저·E2E·라이브 API 테스트는 실행하지 않는다. 사용자가 commit/push한 뒤 Cloudflare 배포에서 동작을 확인한다.

모든 단계마다 관련된 기능만 확인하며 이미 통과한 전체 항목을 반복하지 않는다. 새 변경이 공통 렌더러·저장·좌표계에 영향을 주면 그 영향을 받는 회귀 시나리오를 추가한다. AI의 실제 과금 요청은 무과금 UI 확인과 구분해 실행·비용 결과를 기록한다.

## 4. 0단계 — 제품 정책·UI·공통 계약

목표는 새 구현에 필요한 결정을 먼저 기록해 UI와 엔진이 서로 다른 규칙을 만들지 않게 하는 것이다.

| ID | 세부 작업 | 산출물·완료 기준 | 선행 |
| --- | --- | --- | --- |
| E00-01 | 작업 범위·규격·출력 정책 정리 | 세 원본 규격, 문서/출력 규격, 지원 밖 입력, 크롭·포함/채우기·회전의 예제와 정책표 | 없음 |

| E00-03 | 신규 UI 시안과 상태 전환 작성 | 세 비율의 작업 화면, 도구 옵션·레이어/마스크·AI 후보·저장 오류·내보내기 시안 | E00-02 |

| E00-05 | 저장·서비스 경계 정의 | 문서/자산/버전/출력 API, 프로젝트·인증·비공개 경로, 충돌·부분 성공 상태표 | E00-04 |
| E00-06 | AI 제공자 연결 조건 조사 | 현재 생성 서비스의 입력·마스크 의미·모델 옵션·비용·상태·취소 한계, 신규 어댑터 명세 | E00-02 |

권장 설계 산출물은 `docs/image-editor-design-contracts.md`와 `docs/image-editor-ui-spec.md`다. 기존 코드를 옮기는 목록 대신 새 문서의 JSON 예제·작업 시퀀스·화면 상태를 기준으로 작성한다.

이 단계에서 반드시 기록할 규칙:

1. 원본은 불변 자산으로 고정하고 결과 이미지의 저장 경로와 분리한다.
2. 문서 내용 상태, 현재 도구/화면 상태, 현재 선택 영역, AI 후보 미리보기를 구분한다.
3. 클라이언트 편집 상태의 식별값과 서버 저장 revision을 분리한다. Undo로 저장 시점에 돌아온 경우의 미저장 표시도 정한다.
4. 선택 영역은 문서 좌표의 alpha mask, 레이어 마스크는 레이어 변형과 연결 가능한 별도 자산으로 정의한다. 두 마스크 사이의 변환·샘플링 규칙을 명시한다.
5. 필터·마스크·불투명도·블렌딩·조정·그룹 격리·클리핑의 합성 순서를 작은 기준 이미지로 설명한다.
6. 생성 취소가 UI 대기 중단인지 제공자 실행 취소인지 구분한다. 비용 환급이나 서버 중단을 확인 없이 보장하지 않는다.

**종료 조건:** UI 시안의 모든 주요 동작이 문서·명령·저장·AI 계약에 연결되고 서로 모순되는 정책이 없다. 시안 제작은 후속 구현 작업이며 이번 실행 계획 작성에서 완료했다고 간주하지 않는다.

제안 위치: `public/js/editor/workspace/`, `public/js/editor/tools/`, `public/editor.css`. 초기에는 새 검증용 진입점에서 노출하고 기존 편집기 구현을 새 화면의 기반으로 사용하지 않는다.

**배포 확인:** 세 비율을 가정한 화면에서 패널·도구·입력 포커스가 정상이고, 진입/이탈을 반복해도 리스너·오버레이·미저장 경고가 중복되지 않는다. 실제 이미지 표시와 저장 연결은 다음 단계에서 완료한다.

## 6. 2단계 — 문서·자산·렌더러·이력

| ID | 세부 작업 | 산출물·완료 기준 | 선행 |
| --- | --- | --- | --- |
| E02-01 | 문서 스키마와 내용 상태 작성 | 세 프리셋·레이어 ID·자산 ID·문서 상태, 검증·기본값·불변 변경 규칙 | E00-04 |

이 단계의 픽셀 명령은 공통 기반이다. 일반 브러시 UI는 6단계, 마스크용 최소 브러시는 5단계에서 연결한다. 화면 변경은 렌더 요청으로 모으고 슬라이더·텍스트 입력을 위해 DOM 전체를 다시 만들지 않는다.

**배포 확인:** 세 규격을 각각 열고 이미지 추가·이동·Undo/Redo·줌을 수행한다. 반투명 이미지와 다른 비율의 추가 이미지가 정확하게 표시되며 내보내기용 합성에는 핸들·가이드가 섞이지 않는다. 이 시점의 저장은 아직 서버 저장 완료가 아니다.

| E03-02 | 원본/추가 자산 업로드·조회 | 불변 자산 저장, 문서와 자산 참조 연결, 업로드 중/실패/재시도·누락 자산 표시 | E03-01·E02-02 |
| E03-03 | 문서 revision commit·조회·목록 | baseRevision 조건·요청 ID·불변 manifest, 부분 성공 기록, 동일 요청 재시도·409 충돌 | E03-02·E02-05 |
| E03-04 | 수동/자동 저장 상태 작성 | 문서당 요청 직렬화, 캡처한 상태만 저장 완료, debounce/최대 대기·오류 재시도 | E03-03 |
| E03-05 | 로컬 복구·이동 확인 작성 | IndexedDB 복구본·서버 버전 비교, 로컬/서버 상태 분리, 실패 시 미저장 작업 유지 | E03-04·E01-01 |
| E03-06 | 최근 작업·버전 기록·복원 작성 | 썸네일·정렬·재열기, 저장 버전 미리보기, 새 revision으로 복원·자산 참조 보호 | E03-03~05 |

문서 JSON·이미지·마스크를 D1 한 row에 base64로 넣지 않는다. D1은 목록·현재 revision·저장/연결 상태를 담당하고 실제 자산과 manifest는 R2에 둔다. 신규 스키마 배포 SQL은 구 문서 데이터 이전을 의미하지 않는다. API 상세는 [Cloudflare D1 문서](https://developers.cloudflare.com/d1/worker-api/d1-database/)와 [R2 문서](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/)를 기준으로 설계한다.

구조적 저장 규칙:

- 최신 revision은 조건부 갱신으로 확정한다. 조회 후 무조건 쓰는 방식이나 `MAX(revision)+1`만으로 동시성 제어를 대신하지 않는다.
- 실패한 요청 재전송은 같은 결과를 식별하고 이미 성공한 저장을 중복 생성하지 않는다.
- 단순한 사전 revision 조회만으로 R2·D1 전체 쓰기의 원자성이 보장된다고 취급하지 않는다. 부분 성공 상태·재시도·자산 정리 조건을 명시한다.
- 요청 중 새 편집은 별도 상태로 남기고 저장 완료 응답이 그 변경의 dirty를 해제하지 않게 한다.
- AI 후보·버전·문서가 참조한 자산은 정리 대상에서 제외한다. 첫 출시에서는 명시적 삭제와 참조 확인을 먼저 구현하고 무차별 자동 정리를 도입하지 않는다.

**배포 확인:** 원본+추가 이미지 문서를 저장→재열기해 내용이 동일하다. 저장 중 변경, 두 탭 충돌, 업로드/DB 실패, 오프라인 복구, 이전 버전 복원을 구분한다. 이 확인을 마쳐야 새 엔진·저장 기반이 완료다.

프로젝트의 비용·구독·모델 지원 정책은 서비스 연동 계약으로 준수한다. [Anlas 정책 문서](novelai-anlas-policy.md)는 조사 출발점이며 실제 연결 시 현재 정책·계산 코드와 대조한다. 고정 요금이나 무료 조건을 새 편집기 코드에 임의로 복사하지 않는다.

취소·늦은 결과 규칙:

- UI의 취소와 제공자의 실제 생성 중단을 구분한다.
- 요청 후 편집이 바뀌어도 최신 상태를 자동 덮어쓰지 않는다. 같은 규격이면 명시적으로 레이어 추가, 규격이 달라졌으면 원래 revision의 복제 작업에서 열기를 제공한다.

- 응답 해상도·마스크 좌표가 계약과 다르면 오류로 처리한다. 임의 리사이즈로 맞추지 않는다.

**배포 확인:** 세 규격의 선택 영역 인페인트, 실패·취소·재시도, 생성 중 추가 편집/프리셋 변경/문서 이동, 후보 전환·확정·Undo·재열기를 확인한다. 미리보기와 실제 문서 변경을 구분할 수 있어야 한다.

| `functions/[[path]].js` | 구 편집 API·런타임 스키마 생성 제거, 새 서비스 라우팅 연결 |
| `src/path-migration.js` | 구 문서 테이블 갱신 제거, 새 문서는 불변 자산으로 재열기·출력 경로 관계 처리 |
| `src/image-serving.js`와 목록 경로 | 새 내부 자산 비공개 분류, 기존 보호 경로에 저장 데이터가 남으면 그 보호 유지 |

구 API 제거와 R2 내부 경로의 비공개 보호는 별개다. 구 데이터가 남아 있는 경로를 공개 이미지로 노출시키는 방식으로 정리하지 않는다. 구 DB/R2 데이터의 실제 삭제는 이 계획의 코드 제거 작업에 자동 포함하지 않는다.

**종료 조건:** 신규 편집기만으로 16절 핵심 작업이 완료되고 구 편집 코드에 대한 실행 의존성이 없다. 미완성 P1 기능은 후속 기능으로 조용히 넘기지 않고 출시 범위표에 남겨 해소한다.

## 14. 10단계 — 전문 편집 확장

| ID | 세부 작업 | 산출물·완료 기준 | 선행 |
| --- | --- | --- | --- |
| E10-01 | 복제 도장·힐링·패치 | 기준점·현재/합성 샘플·선택 제한·보정 레이어, 경계 품질·Undo·저장 | E05~06·E09 |
| E10-02 | Levels·Curves·히스토그램·LUT | 편집 가능한 보정 파라미터, 채널/밝기 매핑·마스크·클리핑·캐시 | E06-03~04 |
| E10-03 | 정밀 경계·펜·벡터 마스크 | 머리카락/반투명 경계·색 번짐, 베지어 패스·선택/마스크 변환 | E05-03~05·E07-03 |
| E10-04 | 원근·기울이기·워프·국소 변형 | 변형 모델·핸들·사전 preview·원본 참조·정확한 hit/출력 | E04-03·E09-01 |
| E10-05 | 고급 브러시·리터칭·표현 | 필압·선 보정·프리셋·알파 잠금, 닷지/번·스머지·블러/샤픈, 다각형·확장 스타일·추가 블렌딩 | E06~07 |

각 기능을 별도로 출시 가능하게 나눈다. 예를 들어 도장은 힐링 알고리즘 완성을 기다리지 않고 독립 작업으로 세분화할 수 있다. 기술 검토·화면 조작·품질·저장까지 완료해야 해당 도구를 노출한다. 기존 포토샵 기능의 명칭만 붙이고 다른 결과를 제공하는 방식으로 완료 처리하지 않는다.

## 16. 첫 실용 릴리스의 통합 완료 기준

아래 시나리오는 세 규격을 공통 입력으로 사용한다. 동일한 기능을 확인하는 중복 조합은 줄이되 가로·정사각·세로의 전체 열기→저장→출력 흐름은 각각 확인한다.

| ID | 시나리오 | 확인할 결과 |
| --- | --- | --- |
| R01 | 프로젝트/로컬/드롭/붙여넣기로 원본 열기·빈 작업 생성 | 지원 규격 검증, 다른 규격의 추가 이미지, 프로젝트·원본 관계 |
| R02 | 복수 이미지·그룹·변형·프리셋 변경·저장·재열기 | 좌표·순서·원본 내용·alpha 일치 |
| R03 | 선택·마스크·클리핑으로 캐릭터와 배경 합성 | 선택 연산·경계 수정·변형 연결·선택 밖 보존 |
| R04 | 브러시·채우기·그라데이션·국소 보정·가림 | 명시한 대상, 0값·경계값, 효과 강도·블렌딩·마스크 |
| R05 | 여러 줄 한글 텍스트·도형·테두리·그림자 | IME·폰트 준비·재편집·선 방향·합성 일치 |
| R06 | 인페인트 요청·후보 비교·추가·Undo·재열기 | 후보 비누적, 선택 밖 보존, 자산·요청 설정 연결 |
| R07 | AI 생성 중 편집/규격 변경/문서 이탈·취소·늦은 결과 | 현재 문서 보호·후보 소속·명확한 상태 |
| R08 | 저장 중 새 편집·중복·두 탭·일부 실패·복구·버전 복원 | 캡처한 상태만 저장 완료, 재시도·충돌·최신 복구본 식별 |
| R09 | PNG/JPEG/WebP 다운로드·프로젝트 저장·결과 갱신 | 고정 크기·MIME·alpha/배경·대상 백업·metadata·공개 범위 |
| R10 | 기준 문서·긴 획·후보 전환·진입/이탈 반복 | 반응성·이력 예산·자원 회수, 패널 포커스 유지 |
| R11 | 기본 진입점 교체 후 프로젝트·이미지 상세·기존 생성 기능 사용 | 구 편집 import/API 실행 의존성 없음, 공용 기능 영향 없음 |

기준 문서는 상위 계획의 레이어 20개·마스크 5개·조정/효과 5개다. 이동·줌·변형 30fps 이상, 일반 브러시 시각 반영 p95 50ms 이내는 확인할 목표이며 현재 성능을 보장하는 수치가 아니다. 측정 기기·브라우저·문서·배포를 함께 기록한다.

## 17. 최초 착수 순서와 작업 묶음

| 착수 순서 | 묶음 | 완료 후 다음 판단 |
| --- | --- | --- |
| 1 | E00-01~02 정책·작업 흐름 | 출력 세 규격·크롭·첫 릴리스 기능 범위를 명확히 기록 |
| 2 | E00-03 새 UI 시안 | 세 비율과 선택/AI/저장 상태가 실제 작업 순서에 맞는지 검토 |
| 3 | E00-04~06 문서·저장·AI 계약 | 구현자가 임의 규칙 없이 엔진/서버를 작성할 수 있는지 확인 |
| 4 | E01 새 화면 → E02 문서·렌더러 | 새 모듈만으로 표시·조작·이력이 이어지는지 배포 확인 |
| 5 | E03 저장·복구 | 저장 전후 일치·오류·충돌을 통과한 뒤 편집 도구 확장 |
| 6 | E04~06 합성·선택·보정 | 캐릭터 분리·배경 합성·국소 보정의 완성도 확인 |
| 7 | E07~08 표현·AI | 글자·도형·가림·AI 부분 수정까지 작업 완결성 확인 |
| 8 | E09 출력·통합·교체 | P1 누락 없이 첫 실용 릴리스 완료 여부 판단 |

기간과 담당자는 E00 산출물에 따라 정한다. 먼저 UI 시안·공통 계약·기능 묶음을 확정한 후 기술 난도가 큰 힐링·정밀 마스킹·워프·자동 분리에는 별도 추정을 붙인다. 전체를 동일한 크기의 작업이나 근거 없는 주차로 나누지 않는다.

신규 구현은 위 작업 묶음을 기준으로 반영했다. [설계 계약](image-editor-design-contracts.md)과 [UI 명세](image-editor-ui-spec.md)를 기준으로 구현을 검토하고, 사용자 commit/push 후 배포에서 단계 종료 조건을 확인한다.
